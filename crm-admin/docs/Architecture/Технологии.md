# Технологии

Стек по `pom.xml`, `Dockerfile`, `docker-compose.yml`, `application.yml` и `static/index.html`. Как части связаны — [[Обзор архитектуры]]; переменные и профили — [[Конфигурация]].

## Бэкенд

| Технология | Версия | Зачем |
|---|---|---|
| Java | **21** | records и `switch`-выражения используются активно (DTO, ветвления по каналам) |
| Spring Boot | **3.3.4** (parent) | каркас; версии всех starters управляются parent-ом |
| spring-boot-starter-web | managed | REST `/api/**` + раздача статики SPA |
| spring-boot-starter-data-jpa | managed | JPA/Hibernate + `JdbcTemplate` для нативного SQL; `ddl-auto: none`, `open-in-view: false`, таймзона JDBC `Europe/Moscow` |
| spring-boot-starter-security | managed | form-login, remember-me, `@PreAuthorize` — см. [[Безопасность и RBAC]] |
| spring-boot-starter-validation | managed | `@Valid` на входящих DTO |
| spring-boot-starter-aop | managed | нужен `@EnableMethodSecurity` |
| flyway-core + **flyway-database-postgresql** | managed | миграции `db/migration` (**V1–V25**); сиды `db/seed` (V900+) выведены из обращения; в Flyway 10 постгрес-диалект — отдельный артефакт |
| PostgreSQL JDBC | managed, `runtime` | драйвер; отдельным пулом ходим и во внешнюю прод-БД |
| Lombok | managed, `provided` | геттеры/сеттеры сущностей; исключён из финального jar |
| springdoc-openapi-starter-webmvc-ui | **2.6.0** | Swagger UI на `/swagger-ui.html` — живая версия [[REST API]] |
| spring-boot-starter-test, spring-security-test | managed, `test` | тестовый контур |

Сборка: Maven, `finalName=crm-admin` → `target/crm-admin.jar`.

Отдельно стоит отметить, чего в стеке **нет**: библиотеки для Excel (Apache POI) не подключено — выгрузка «ЧЕК СМС траффик» собирается штатным `java.util.zip` переписыванием XML-частей внутри готового `.xlsx`-шаблона, см. [[Отчёты]].

## База данных

- **PostgreSQL 16** (`postgres:16`) во всех трёх контурах.
- Активно используются постгрес-специфичные вещи: `jsonb`, массивы (`text[]`, `bigint[]`), `interval`, `GENERATED BY DEFAULT AS IDENTITY`, `ON CONFLICT … DO UPDATE`, `to_jsonb(t)`, GUC через `set_config('app.current_user', …)`.
- Flyway: `schemas: notice,callcenter,retention,arch,app`, `default-schema: app`, `create-schemas: true`; остальные схемы (`tracker`, `scheduler`, `template`, `commapi`, `flow`, `dictionary`) создают сами миграции.
- Профили: `docker` — миграции + сиды, `out-of-order: true` (сиды заняли версии V900+ раньше, чем появились новые схемные); `prod` — **Flyway выключен полностью**.

## Фронтенд

Без фреймворка и без сборщика: статика отдаётся Spring Boot как есть, этапа «сборка фронта» не существует.

| Что | Где | Зачем |
|---|---|---|
| Vanilla JS (ES5-стиль, IIFE) | `static/api.js`, `static/js/*.js`, `static/wizard.js`, `static/journeys.js`, `static/admin-users.js`, `static/combobox.js` | вся логика панели |
| **Drawflow (вендорен)** | `static/drawflow.min.js` / `.css` | канва Flow Builder; положен в репозиторий локально — «без зависимости от CDN» |
| Собственный combobox | `static/combobox.js` | редактируемые селекты с подсказками из справочников |
| CSS-переменные + рукописные стили | `static/css/shell.css`, `css/section-*.css` | оболочка и темы; стили разделов изолированы через `@scope (#sec-…)` |
| Chart.js 4.4.1 | cdnjs | графики дашборда |
| SheetJS (xlsx) 0.18.5 | cdnjs | импорт/экспорт xlsx в тепловой карте |
| Шрифт Golos Text | fonts.googleapis.com | оформление |

**Внешние зависимости фронта существуют** и это осознанный компромисс, а не исходный замысел: Chart.js и SheetJS подключены с `cdnjs.cloudflare.com`, шрифт — с Google Fonts. В закрытом контуре с TLS-инспекцией они могут не загрузиться: шрифт деградирует до системного без потери функциональности, а дашборд и импорт/экспорт тепловой карты — нет. Вендорить их так же, как Drawflow, — открытый follow-up.

## Инфраструктура

- **Docker, multi-stage `Dockerfile`**: сборка в `maven:3.9-eclipse-temurin-21` (кеш зависимостей прогревается по одному `pom.xml`), рантайм `eclipse-temurin:21-jre` под непривилегированным пользователем `app`, `EXPOSE 8080`.
- **docker compose** — три стека из одного образа `crm-admin:local`; на сервере поверх кладётся `docker-compose.server.yml` (nginx :80 + `restart: unless-stopped`). Подробности — [[Среды и деплой]].
- Скрипты сопровождения: `scripts/reset-test.sh`, `scripts/refresh-preprod.sh`, `scripts/promo_import.sql`.

## Почему так

1. **Один jar = всё приложение.** SPA внутри jar-а убирает CORS, отдельный веб-сервер и деплой фронта.
2. **Минимум рантайм-зависимостей.** Замена Appsmith задумывалась как self-hosted: вендореный Drawflow, свой combobox вместо UI-библиотек, БД в соседнем контейнере.
3. **Flyway — единственный владелец схемы.** `ddl-auto: none` + прод-идентичные DDL дают гарантию «то, что заработало на test, работает на проде»; на проде миграции выключены.
4. **Lombok и records** сокращают шаблонный код: сущности — Lombok, DTO — Java records.
