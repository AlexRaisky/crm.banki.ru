# Технологии

Стек по `pom.xml`, `Dockerfile`, `docker-compose.yml`, `src/main/resources/application.yml`, `nginx/crm-admin.conf`, `scripts/` и `static/index.html`. Как части связаны — [[Обзор архитектуры]]; переменные и профили — [[Конфигурация]]; контуры и раскатка — [[Среды и деплой]].

## Бэкенд

| Технология | Версия | Зачем |
|---|---|---|
| Java | **21** | records (DTO) и `switch`-выражения (ветвления по каналам и capability) |
| Spring Boot | **3.3.4** (parent) | каркас; версии всех starters управляются parent-ом |
| spring-boot-starter-web | managed | REST `/api/**` + раздача статики SPA |
| spring-boot-starter-data-jpa | managed | JPA/Hibernate для `AppUser`/`Role`/`Journey` + `JdbcTemplate` для всего остального SQL; `ddl-auto: none`, `open-in-view: false`, таймзона JDBC `Europe/Moscow` |
| spring-boot-starter-security | managed | form-login, remember-me, `@EnableMethodSecurity` — см. [[Безопасность и RBAC]] |
| spring-boot-starter-validation | managed | `@Valid` на входящих DTO, ошибки собирает `web/ValidationErrorHandler` |
| spring-boot-starter-aop | managed | нужен `@EnableMethodSecurity` |
| flyway-core + **flyway-database-postgresql** | managed | миграции `db/migration` (**V1–V54**); в Flyway 10 постгрес-диалект — отдельный артефакт |
| PostgreSQL JDBC | managed, `runtime` | драйвер; отдельными соединениями ходим во внешние базы (прод-БД шаблонов, crmdb, DWH) |
| Lombok | managed, `provided` | геттеры/сеттеры сущностей; исключён из финального jar |
| springdoc-openapi-starter-webmvc-ui | **2.6.0** | Swagger UI на `/swagger-ui.html` — живая версия [[REST API]] |
| spring-boot-starter-test, spring-security-test | managed, `test` | объявлены в `pom.xml` |

Сборка: Maven, `finalName=crm-admin` → `target/crm-admin.jar`.

Два факта, которые видно прямо в дереве проекта:

- **Автотестов нет.** В `src/` лежит только `main`; каталога `src/test` не существует, хотя тестовые зависимости в `pom.xml` объявлены. Проверка — ручная, на контуре test.
- **Библиотеки для Excel (Apache POI) нет.** Выгрузка «ЧЕК СМС траффик» собирается штатным `java.util.zip`: панель переписывает XML-части внутри готового шаблона `src/main/resources/reports/sms-check-template.xlsx` (≈4 МБ). См. [[Отчёты]].

Внутрь jar-а, кроме статики и миграций, попадают ещё два ресурса: шаблон отчёта (выше) и `build-info.json` — отметка о собранном коммите, которую перед `docker build` пишет `scripts/build.sh`. В репозитории её нет (`.gitignore`), внутри контейнера git недоступен (`.git` исключён `.dockerignore`), поэтому без `build.sh` раздел «Выкатки» честно отвечает «версия неизвестна».

## База данных

- **PostgreSQL 16** (`postgres:16`) во всех трёх контурах.
- Активно используются постгрес-специфичные вещи: `jsonb` (11 миграций), массивы (`text[]`, `bigint[]`), `interval`, `GENERATED BY DEFAULT/ALWAYS AS IDENTITY`, `ON CONFLICT … DO UPDATE`, `to_jsonb(t)`, частичные индексы (`WHERE run_status IN (…)`), `FOR UPDATE SKIP LOCKED` (очередь выкатов), GUC через `set_config('app.current_user', …)`, `ALTER TABLE … SET SCHEMA` (V43), `to_regclass` вместо «попробовать и поймать».
- Flyway: `schemas: notice,callcenter,retention,arch,app`, `default-schema: app`, `create-schemas: true`. Остальные схемы (`tracker`, `scheduler`, `template`, `commapi`, `flow`, `dictionary`, `reference`) создают сами миграции.
- Профили: `docker` — только `classpath:db/migration`, `out-of-order: true`; `prod` — **Flyway выключен полностью**. Правила жизненного цикла схемы — [[Среды и деплой]].
- Каталог `src/main/resources/db/seed` (V900, V901) физически остался в репозитории, но **из `locations` убран** и не применяется; записи о нём в истории вычищает `config/FlywaySeedCleanup` перед `migrate`.

## Фронтенд

Без фреймворка и без сборщика: статика отдаётся Spring Boot как есть, этапа «сборка фронта» не существует. Кеширование задано глобально в `application.yml` — `spring.web.resources.cache.cachecontrol.no-cache: true`, чтобы после выката браузер не показывал старую панель из своего кеша (условный запрос + 304, а не полная перекачка).

| Что | Где | Зачем |
|---|---|---|
| Vanilla JS (IIFE-стиль) | `static/api.js`, `static/js/*.js`, `static/wizard.js`, `static/journeys.js`, `static/admin-users.js`, `static/combobox.js` | панель |
| Vanilla JS настроечной админки | `static/settings/*.js` (`deploy.js`, `runner.js`, `settings-pack.js`, `changes.js`, `integrations.js`, `health.js`, `refs.js`, `backlog.js`, `db-explorer.js`, `scheme-builder.js`, `object-manager.js`) | `/settings` — [[Страница настроек (settings)]] |
| **Drawflow (вендорен)** | `static/drawflow.min.js` / `.css` | канва Flow Builder; лежит в репозитории локально |
| Собственный combobox | `static/combobox.js` | редактируемые селекты с подсказками из справочников |
| CSS-переменные + рукописные стили | `static/css/shell.css`, `css/section-*.css`, `settings/scheme-builder.css`, `settings/object-manager.css` | оболочка и темы; стили разделов изолированы через `@scope (#sec-…)` |
| Chart.js 4.4.1 | cdnjs | графики дашборда |
| SheetJS (xlsx) 0.18.5 | cdnjs | импорт/экспорт xlsx в тепловой карте |
| Шрифт Golos Text | fonts.googleapis.com | оформление (подключён и в `index.html`, и в `settings/index.html`) |

**Внешние зависимости фронта существуют** — осознанный компромисс, а не исходный замысел: Chart.js и SheetJS подключены с `cdnjs.cloudflare.com`, шрифт — с Google Fonts. В закрытом контуре с TLS-инспекцией они могут не загрузиться: шрифт деградирует до системного без потери функциональности, а дашборд и импорт/экспорт тепловой карты — нет. Вендорить их так же, как Drawflow, — открытый follow-up.

## Инфраструктура

- **Docker, multi-stage `Dockerfile`**: сборка в `maven:3.9-eclipse-temurin-21` (кеш зависимостей прогревается по одному `pom.xml`, `|| true` — чтобы недоступный плагин не ронял сборку), рантайм `eclipse-temurin:21-jre` под непривилегированным пользователем `app`, `EXPOSE 8080`, `ENTRYPOINT java -jar /app/app.jar`.
- **docker compose** — три стека из одного образа `crm-admin:local`; на сервере поверх кладётся `docker-compose.server.yml` (nginx :80 + `restart: unless-stopped`).
- **nginx 1.27-alpine** — только на сервере: gzip для 2.4 МБ статики, `proxy_http_version 1.1` с пустым `Connection`, `proxy_read_timeout 300s` (должен быть больше самого длинного бюджета приложения — сейчас 130 с у отчёта «ЧЕК СМС траффик»), `location = /nginx-health`.
- **systemd** — `scripts/crm-deploy-runner.service` (`Type=oneshot`) + `.timer` (раз в минуту): обработчик очереди выкатов на самом хосте. Панель docker не трогает; см. [[Среды и деплой]].
- **bash-скрипты сопровождения** в `scripts/`: `build.sh`, `deploy-runner.sh`, `reset-test.sh`, `refresh-preprod.sh`, `sync-tables.sh`, `notice-psql.sh` + `lib-notice-conn.sh`, `superadmin-rollout.sh`, `promo_import.sql`. Разбор — [[Среды и деплой]].

## Внешние системы, с которыми говорит панель

| Куда | Чем | Заметка |
|---|---|---|
| Прод-БД шаблонов (`notice.*`, `callcenter.*`) | JDBC, свой пул в `service/prod/ProdDbService` | адрес и учётка — из `app.db_connection` либо `PROD_DB_*` |
| `crmdb` (события) | JDBC, `service/prod/EventDbService` | импорт и перелив событий |
| DWH (отчёт «ЧЕК СМС траффик») | JDBC, `service/SmsCheckReportService` | таймаут запроса 120 с |
| Jira Data Center | `java.net.http.HttpClient`, `service/jira/JiraClient` | REST + `createmeta`, PAT сервисной учётки |
| Tableau | встраивание `<tableau-viz>` на фронте | сервер и токен — в `app.panel_settings` |
| Соседние контуры (prod/preprod/test) | `HttpClient` по внутренней сети compose | `GET /api/build`, `GET /api/schema/ddl/drift-peer` с `X-Peer-Token` |

Никаких брокеров, кешей и очередей поверх БД нет: очередь синка (`app.prod_sync`) и очередь выкатов (`app.deploy_log`) — обычные таблицы, которые опрашивают `@Scheduled` и systemd-таймер соответственно.

## Почему так

1. **Один jar = всё приложение.** SPA внутри jar-а убирает CORS, отдельный веб-сервер и деплой фронта.
2. **Минимум рантайм-зависимостей.** Замена Appsmith задумывалась как self-hosted: вендореный Drawflow, свой combobox вместо UI-библиотек, БД в соседнем контейнере, xlsx без POI.
3. **Flyway — единственный владелец схемы.** `ddl-auto: none` + прод-идентичные DDL дают гарантию «то, что заработало на test, работает на проде»; на проде миграции выключены. Исключение — Scheme Builder, который выполняет DDL в рантайме, но только в границах своего реестра `app.schema_owned`.
4. **Docker панели не даётся.** Сокет docker в контейнере равен root на хосте, поэтому кнопка «Выкатить» пишет задание в таблицу, а команды выполняет bash-скрипт на самом сервере.
5. **Lombok и records** сокращают шаблонный код: сущности — Lombok, DTO — Java records.
