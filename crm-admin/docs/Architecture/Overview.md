# Overview

Самописный сервис на **Java/Spring**, заменяющий рабочую админку маркетинговых коммуникаций из **Appsmith (v2)**. Цель — убрать «костыли» v2 (динамический UPDATE строками, циклические INSERT «цепочек», хардкод доступа по email) и перенести бизнес-логику в нормальный бэкенд, сохранив проверенный UX/UI из прототипа **v1** (в стиле Salesforce Lightning).

## Цели

1. Все CRUD-операции из v2 переписаны на Java и подключены к экрану **«Мастер коммуникаций»**.
2. **«Список шаблонов»** из v2 работает на экране «Список шаблонов» v1.
3. Весь UX/UI берётся из **v1**.
4. **OneLink Builder** из v1 переносится **1:1, без изменений** (полностью клиентский, бэкенд не нужен). См. [[Frontend Overview]].
5. **RBAC**: роли reader / editor / admin; админ поперсонально назначает разделы и роль. См. [[RBAC]].
6. **Дашборд — вне скоупа** (оставляем демо-раздел v1 как есть).
7. Всё в **Docker** для лёгкого развёртывания на сервере. См. [[Развёртывание (Docker)]].

## Архитектура: 2 контейнера

Один тип деплоя — **два контейнера** (`app` + `postgres`); Spring Boot сам раздаёт статику фронта из `src/main/resources/static/`.

- **Backend:** Java 21, Spring Boot 3.3.x, Spring Security (form-login + сессия, BCrypt), Spring Data JPA/Hibernate, Flyway, PostgreSQL-драйвер, springdoc-openapi (Swagger UI). Подробнее — [[Tech Stack]] и [[Backend Overview]].
- **Frontend:** статика v1 (`index.html` + ассеты), раздаётся тем же приложением. Два раздела перепаиваются на REST (`[[REST API]]`), OneLink остаётся байт-в-байт. См. [[Frontend Overview]].
- **База данных:** сначала своя PostgreSQL в `docker-compose`, схема 1:1 по проду; позже переключение на прод-БД сменой env. См. [[Схема БД]].

## Как связаны слои

- Фронт после входа зовёт `GET /api/me` → роль + разрешённые разделы → строит навигацию server-driven. См. [[RBAC]].
- Разделы «Мастер коммуникаций» и «Список шаблонов» работают через REST `/api/templates/**`. См. [[REST API]].
- Мутирующие операции выставляют `app.current_user` для аудита в `arch.arch_log`. См. [[Схема БД]].

## Вне скоупа (сейчас)

Дашборд; корпоративный SSO/LDAP (сейчас локальная аутентификация с заделом на будущее); панель отклонений и OneLink на бэкенде (OneLink остаётся клиентским 1:1); локальный вендоринг CDN-библиотек.
