# Шпаргалка: что и где смотреть

Рабочий справочник по эксплуатации и разбору проблем. Подробные разборы — в остальных заметках ([[Флоу системы]], [[Материализация (Flow)]], [[Схема БД]]).

---

## 1. Контуры

| Контур | Адрес | БД-контейнер | Назначение |
|---|---|---|---|
| prod | домен (через nginx :80) | `crm-admin-db-prod` | боевой, единственный смотрит наружу |
| preprod | 127.0.0.1:8081 | `crm-admin-db-preprod` | обкатка перед продом |
| test | 127.0.0.1:8082 | `crm-admin-db-test` | эксперименты |

Контуры полностью независимы: свои БД, свои пользователи, свои шаблоны. Данные между ними не ходят.

Доступ к preprod/test с рабочей машины:
```bash
ssh -L 8081:127.0.0.1:8081 -L 8082:127.0.0.1:8082 user@сервер
```

## 2. Где какие данные

### Шаблоны — единственный источник `template.d_template`

26 колонок: ядро типизированное + `channel_props jsonb` для канальных полей.

| Группа | Колонки |
|---|---|
| Ключ | `channel` (sms/push/email/cc), `code` — вместе UNIQUE; `id` — суррогатный |
| Имена | `communication_name`, `campaign_name` (в проде это `source_type`) |
| Классификация | `communication_type`, `business_communication_type`, `trigger_type`, `product_type[]`, `partner_name`, `touch_point`, `aff_sub3`, `sending_day` |
| Флаги | `marketplace`, `dialog`, `loyalty`, `national_rating`, `news`, `mobile_app`, `night_send`, `permanent_exclude`, `active_flag` |
| Канальное | `channel_props`: sms → `msg_text`, `sender_name`; push → `title`, `deep_link`, `webview_url`; email → `subject`, `email_from`, `letteros_id`, `is_service`, `is_info`; кц → `segment_descr`, `source_system`, `host_id`, `kvint_campaign_id` |

```sql
-- что заведено
select channel, code, communication_name, campaign_name, active_flag from template.d_template order by channel, code;
-- канальные поля конкретного шаблона
select channel_props from template.d_template where channel='sms' and code=5;
```

### Очередь синка с продом — `app.prod_sync`

`id, channel, operation, local_code, prod_code, payload, status, attempts, last_error, created_by, timestamp_cr, timestamp_upd`

- `operation` — INSERT / UPDATE / DELETE; `status` — PENDING / OK / ERROR;
- `payload` — строка уже в **прод-структуре** (то, что уедет);
- `local_code` — код у нас, `prod_code` — код, присвоенный продом.

### Остальное

| Данные | Таблица | Кто пишет |
|---|---|---|
| Справочники форм | `dictionary.d_communication_name`, `dictionary.d_touch_point` | руками (SQL), сид — миграция V10 |
| Пользователи и права | `app.users`, `app.user_sections` | «Управление доступом», `AdminBootstrap` |
| Схемы цепочек | `app.journeys` (jsonb `definition`, `kind`, `continues_journey_id`) | Flow Builder |
| Событие цепочки и обвязка | `flow.d_event`, `d_event_delivery`, `d_event_schedule`, `d_event_step`, `d_event_template`, `d_event_definition` | материализация |
| Журнал материализации | `flow.t_materialization` (наша сущность ↔ строка слоя B) | материализация |
| Копии процессных таблиц | схемы `tracker`, `scheduler`, `template.d_template_mapping*`, `commapi` | материализация |
| Аудит всех операций | `arch.t_admin_log` (`table_name`, `operation`, `old_row`, `action_user`, `timestamp_cr`) | все сервисы |
| Настройки панели | `app.panel_settings` (ключ → jsonb) | `/settings` |

Канальные таблицы `notice.*` / `callcenter.*` — **историческая копия**, панель их не читает и не пишет.

## 3. Сервисы бэкенда

Путь: `src/main/java/ru/banki/crm/`

### Шаблоны

| Класс | Ключевые методы | Что делает / что трогает |
|---|---|---|
| `service/TemplateStore` | `list`, `get`, `insert`, `update`, `delete`, `nextCode`, `rowJson`, `prodPayload` | Всё чтение и запись `d_template`. `update` частичный: незаполненные поля не затирают, `channel_props` мержится. `prodPayload` собирает прод-строку: `channel_props` + ядро под прод-именами + бизнес-код |
| `service/TemplateService` | `list`, `get`, `create`, `update`, `delete`, `createChain` | Бизнес-слой: проверки, код через `nextCode`, аудит, постановка в очередь. `createChain` — N шаблонов по дням одной транзакцией |
| `service/UnifiedTemplateService` | `channelTable`, `prodDefaults`, `enqueueProdSync`, `applyProdCode`, `deleteUnified` | Правила каналов: таблица прода, колонка кода, лимит нумерации (sms/email — до 10000). `prodDefaults` — поля, которые прод требует непустыми (email → `subject`). `applyProdCode` переписывает код после доставки: в `d_template` и в неотправленном хвосте очереди |
| `service/DictionaryService` | `partnerNames`, `ccSegments`, `communicationNames`, `touchPoints` | Значения для форм из `dictionary.*` и `d_template` |
| `service/NamingService` | — | Серверная генерация `campaign_name` (основная логика — на фронте) |

### Синк с продом

| Класс | Ключевые методы | Что делает |
|---|---|---|
| `service/prod/ProdDbService` | `configured`, `health`, `apply` (внутри `insert`/`update`/`maxPlusOne`/`tableColumns`) | Отдельный пул к внешней прод-БД. `health` — коннект, задержка, наличие 4 таблиц. `insert` перечисляет только заполненные колонки (чтобы не перебить DEFAULT) и выдаёт коды: sms/email — в диапазоне до 10000, push — сквозной, кц — id по счётчику |
| `service/prod/ProdSyncService` | `tick` (раз в 20 с), `process`, `stats` | Забирает PENDING, доставляет, ставит OK/ERROR, до 10 попыток |

### Цепочки

| Класс | Ключевые методы | Что делает |
|---|---|---|
| `service/flow/MaterializationService` | `validate`, `preview`, `materialize`, `expandedComms`, `resolveSource` | Проверка схемы, предпросмотр будущих строк, запись слоёв A и B. `expandedComms` разворачивает Subflow, `resolveSource` берёт source из шаблона первой comm-ноды |
| `service/DbJourneyService` / `MockJourneyService` | `list`, `get`, `create`, `update`, `delete` | Хранение схем в `app.journeys` (мок — только для сред без БД-хранения) |

### Доступ и служебное

| Класс | Что делает |
|---|---|
| `service/UserService` | Пользователи, правила ролей (кто кого может менять), проверка домена почты |
| `config/AdminBootstrap` | Создаёт супер-админа из `.env`, восстанавливает ему роль, понижает прежнего |
| `security/SecurityConfig` | Кто куда пускается, форма входа, remember-me |
| `security/AppUserPrincipal` | Роли; SUPER_ADMIN дополнительно получает ROLE_ADMIN |
| `security/AccessGuard` + `service/Sections` | Проверка доступа к разделу. Разделы: `home`, `admin`, `templates`, `dashboard`, `deviations`, `onelink`, `journeys`, `access` |
| `service/AdminLogService` | Запись в `arch.t_admin_log` |
| `service/AuditContext` | Прокидывает пользователя в `arch.arch_log` |

## 5. Потоки данных

**Сохранение шаблона** (одна транзакция):
1. `TemplateService.create/update` → `TemplateStore` пишет `template.d_template`;
2. `AdminLogService` → строка в `arch.t_admin_log`;
3. `UnifiedTemplateService.enqueueProdSync` → строка в `app.prod_sync` (только если задан `PROD_DB_URL`);
4. далее вне транзакции: `ProdSyncService` (раз в 20 с) → `ProdDbService` → INSERT/UPDATE/DELETE в прод-БД → код от прода возвращается и переписывается у нас.

**Материализация цепочки:** Flow Builder → `POST /api/flow/preview` (показывает будущие строки) → `POST /api/flow/materialize` → `flow.*` (слой A) + копии процессных таблиц (слой B) + `flow.t_materialization` + аудит. Повторная материализация идемпотентна: старые строки удаляются по журналу.

## 7. Конфигурация (`.env`)

| Переменная | Смысл |
|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | панельные БД (контейнеры), менять только вместе с томами |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | супер-админ; пароль применяется только при первом создании |
| `APP_EMAIL_DOMAIN` | домен почты (пусто = `banki.ru`, проверка обязательна) |
| `PROD_DB_URL`, `PROD_DB_USER`, `PROD_DB_PASSWORD` | внешняя прод-БД; пусто = синк выключен, очередь не ведётся |
| `PROD_DB_CONNECT_TIMEOUT_MS` | таймаут подключения к проду (по умолчанию 20000) |
| `REMEMBER_ME_KEY`, `REMEMBER_ME_DAYS`, `SESSION_TIMEOUT` | сессии и «запомнить меня» |
| `APP_BIND`, `DB_BIND` | на сервере `127.0.0.1` — наружу только nginx |
| `JOURNEYS_MOCK`, `FEATURES_DEV`, `APP_ENV` | режим цепочек, dev-разделы, имя контура |

Схема БД — миграции `src/main/resources/db/migration/`: V1 шаблоны · V2 пользователи · V3 цепочки · V4 аудит · V5–V6 слои процесса · V7 настройки панели · V8 единый справочник и очередь · V9 очистка очереди · V10 справочники форм · V11 роль супер-админа.

## 8. Диагностика

**Первый экран при любой проблеме с продом:** `/settings` → Диагностика («Проверить соединение», «Доставить очередь сейчас», счётчики).

```bash
# состояние контейнеров
docker compose ps
# лог приложения
docker logs crm-admin-app-prod --tail 50
# очередь синка
docker exec crm-admin-db-prod psql -U crm -d crm -c \
 "select id, channel, operation, local_code, prod_code, status, attempts, left(coalesce(last_error,''),200) from app.prod_sync order by id desc limit 10;"
# разбудить упавшие
docker exec crm-admin-db-prod psql -U crm -d crm -c \
 "update app.prod_sync set status='PENDING', attempts=0, last_error=null where status='ERROR';"
# очистить очередь
docker exec crm-admin-db-prod psql -U crm -d crm -c "delete from app.prod_sync;"
# последние операции пользователей
docker exec crm-admin-db-prod psql -U crm -d crm -c \
 "select timestamp_cr, action_user, table_name, operation from arch.t_admin_log order by id desc limit 15;"
# проверить связь с продом напрямую
docker run --rm -e PGPASSWORD='пароль' postgres:16 psql -h ХОСТ -p ПОРТ -U ЮЗЕР -d БАЗА -c "select 1;"
```

| Симптом | Причина / что смотреть |
|---|---|
| 502 в браузере | приложение стартует ~1 мин; если стартовало — `docker restart crm-admin-nginx` |
| Шаблон не в проде | `last_error` в очереди: NOT NULL-колонка → добавить в `prodDefaults`; permission denied → права пользователя БД; duplicate key → конфликт кода |
| «Доступно: НЕТ» | сеть или креды — проверить прямым psql (выше) |
| Не заводится пользователь | почта не `@banki.ru` |
| Нет раздела «Цепочки» | доступен только ADMIN и выше |
| Роль ADMIN недоступна в списке | назначать администраторов может только супер-админ |

## 9. Частые правки — куда идти

| Задача                                         | Где править                                                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Поля формы, значения по умолчанию              | `static/index.html` (разметка форм) + `static/wizard.js`                                                                    |
| Формулы `communication_name` / `campaign_name` | `js/wizard-forms.js`: `updateComNameFromContext`, `computeCampaignName`; в карточке — `js/template-details.js`: `sfdComputeComname`, `sfdComputeCampaignName` |
| Подсказки к полям мастера                      | `js/wizard-forms.js` (`FIELD_HELP_TEXTS`)                                                                                  |
| Стили раздела                                  | `css/section-<раздел>.css` (внутри `@scope (#sec-…)`), общие переменные и тема — `css/shell.css`                            |
| Правила кодов, обязательные поля прода         | `service/UnifiedTemplateService` (`channelTable`, `prodDefaults`)                                                           |
| Что уезжает в прод                             | `service/TemplateStore.prodPayload`                                                                                         |
| Как строится INSERT в прод                     | `service/prod/ProdDbService.insert`                                                                                         |
| Пополнить справочники                          | `insert into dictionary.d_touch_point (value) values ('…');` — появится в формах сразу                                      |
| Права, роли                                    | `service/UserService` + `security/SecurityConfig`                                                                           |
| Пункты меню, разделы                           | `js/shell.js` (массив `NAV`) + `service/Sections`                                                                           |
| Узлы Flow Builder                              | `static/journeys.js` (`NODE_TYPES`) + `service/flow/MaterializationService`                                                 |

## 10. Обновление и доступ к БД

```bash
# обновить сервер
cd crm.banki.ru/crm-admin && git pull
docker compose -f docker-compose.yml -f docker-compose.server.yml build app-prod
docker compose -f docker-compose.yml -f docker-compose.server.yml up -d app-prod app-preprod app-test

# только правки .env — пересборка не нужна
docker compose -f docker-compose.yml -f docker-compose.server.yml up -d --force-recreate app-prod

# БД с рабочей машины
ssh -L 15432:127.0.0.1:5432 user@сервер   # затем DBeaver: localhost:15432, база crm, пользователь crm
```

Миграции накатываются автоматически при старте. Бэкап: `docker exec crm-admin-db-prod pg_dump -U crm crm | gzip > backup_$(date +%F).sql.gz`
