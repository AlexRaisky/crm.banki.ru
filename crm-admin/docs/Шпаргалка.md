# Шпаргалка: что и где смотреть

Быстрый справочник по эксплуатации. Подробности — в остальных заметках, ссылки внизу.

## Контуры

| Контур | Адрес | Назначение |
|---|---|---|
| prod | домен (nginx :80) | боевой; только он смотрит наружу |
| preprod | 127.0.0.1:8081 | обкатка перед продом |
| test | 127.0.0.1:8082 | эксперименты |

Preprod/test с рабочей машины — по SSH-туннелю:
`ssh -L 8081:127.0.0.1:8081 -L 8082:127.0.0.1:8082 user@сервер`

## Где лежат данные

| Что | Где |
|---|---|
| Шаблоны (единственный источник) | `template.d_template` — ядро колонками + `channel_props` jsonb |
| Справочники форм | `dictionary.d_communication_name`, `dictionary.d_touch_point` |
| Очередь синка с продом | `app.prod_sync` |
| Пользователи и права | `app.users`, `app.user_sections` |
| Цепочки (схемы) | `app.journeys`; событие и обвязка — схема `flow` |
| Аудит всех операций | `arch.t_admin_log` |
| Настройки панели | `app.panel_settings` |

Канальные таблицы `notice.*` / `callcenter.*` в панели больше не используются — это история.

## Синхронизация с прод-БД

- **Проверить связь:** панель → `/settings` → Диагностика → «Проверить соединение». Там же «Доставить очередь сейчас» и счётчики PENDING / ERROR / OK.
- **Как работает:** сохранение шаблона → запись в `d_template` + строка в очередь → доставщик раз в ~20 с делает INSERT/UPDATE/DELETE в прод.
- **Коды присваивает прод:** sms и email — в диапазоне до 10000, push — сквозной счётчик, у КЦ id по счётчику, а segment из формы. Локальный код после доставки переписывается на прод-код.

Посмотреть очередь:
```bash
docker exec crm-admin-db-prod psql -U crm -d crm -c \
 "select id, channel, operation, local_code, prod_code, status, attempts, left(coalesce(last_error,''),200) from app.prod_sync order by id desc limit 10;"
```
Разбудить упавшие записи:
```bash
docker exec crm-admin-db-prod psql -U crm -d crm -c \
 "update app.prod_sync set status='PENDING', attempts=0, last_error=null where status='ERROR';"
```
Очистить очередь:
```bash
docker exec crm-admin-db-prod psql -U crm -d crm -c "delete from app.prod_sync;"
```

## Роли

| Роль | Может |
|---|---|
| READER | только смотреть назначенные разделы |
| EDITOR | + заводить и править шаблоны |
| ADMIN | + управлять пользователями (кроме администраторов) |
| SUPER_ADMIN | + назначать и снимать администраторов |

Супер-админом становится учётка из `ADMIN_EMAIL` — роль восстанавливается при каждом старте, прежний супер-админ автоматически понижается. Наружу (список пользователей, API) он выглядит обычным админом.

Почта только `@banki.ru`. Свой пароль меняется кнопкой «Пароль» в шапке.

## Обновление сервера

```bash
cd crm.banki.ru/crm-admin && git pull
docker compose -f docker-compose.yml -f docker-compose.server.yml build app-prod
docker compose -f docker-compose.yml -f docker-compose.server.yml up -d app-prod app-preprod app-test
```
Правки в `.env` подхватываются пересозданием контейнера (`--force-recreate`), пересборка не нужна. Миграции БД накатываются сами при старте.

## Если что-то не работает

| Симптом | Куда смотреть |
|---|---|
| 502 в браузере | приложение стартует (~1 мин): `docker logs crm-admin-app-prod --tail 20`, ждём «Started CrmAdminApplication». Если стартовало, а 502 остался — `docker restart crm-admin-nginx` |
| Шаблон не уехал в прод | `/settings` → Диагностика; затем `last_error` в `app.prod_sync` |
| «Доступно: НЕТ» у прод-БД | сеть/креды: `docker run --rm -e PGPASSWORD='…' postgres:16 psql -h ХОСТ -p ПОРТ -U ЮЗЕР -d БАЗА -c "select 1;"` |
| Не пускает нового пользователя | почта не на `@banki.ru` |
| Не видно раздела «Цепочки» | он только для роли ADMIN и выше |
| Контейнеры и их состояние | `docker compose ps`, логи — `docker logs <имя> --tail 50` |

## Подключиться к БД с рабочей машины

```bash
ssh -L 15432:127.0.0.1:5432 user@сервер     # прод-контур панели
```
DBeaver: host `localhost`, port `15432`, база `crm`, пользователь `crm`, пароль из `.env` (`DB_PASSWORD`).

## Где что в коде

Корень проекта — `crm-admin/`. Бэкенд: `src/main/java/ru/banki/crm/`, фронт: `src/main/resources/static/`.

### Бэкенд

| Файл | За что отвечает |
|---|---|
| `service/TemplateStore.java` | **Хранилище шаблонов**: чтение/запись `d_template`, маппинг DTO ↔ `channel_props`, сборка прод-строки (`prodPayload`), выделение кода (`nextCode`) |
| `service/TemplateService.java` | CRUD шаблонов и цепочка дней: валидация, аудит, постановка в очередь синка |
| `service/UnifiedTemplateService.java` | Таблицы каналов и правила кодов (`channelTable`: имя таблицы, колонка кода, лимит 10000), обязательные поля прода (`prodDefaults`), очередь (`enqueueProdSync`), переписывание кода после доставки |
| `service/prod/ProdDbService.java` | Подключение к прод-БД, проверка связи (`health`), сами INSERT/UPDATE/DELETE, нумерация кодов |
| `service/prod/ProdSyncService.java` | Фоновая доставка очереди, ретраи, статусы |
| `service/flow/MaterializationService.java` | Цепочки: валидация, предпросмотр, материализация в слои A/B |
| `service/UserService.java` | Пользователи: правила ролей, супер-админ, домен почты |
| `service/DictionaryService.java` | Справочники для форм |
| `service/AdminLogService.java` | Запись в `arch.t_admin_log` |
| `service/NamingService.java` | Серверная генерация `campaign_name` |
| `config/AdminBootstrap.java` | Создание супер-админа из `.env`, понижение прежнего |
| `security/SecurityConfig.java` | Кто куда пускается, форма входа, remember-me |
| `security/AppUserPrincipal.java` | Роли (SUPER_ADMIN получает и ROLE_ADMIN) |
| `web/*Controller.java` | Эндпоинты: `TemplateController`, `FlowController`, `ProdSyncController` (`/api/admin/prod-db/*`), `AdminUserController`, `PanelSettingsController`, `DictionaryController`, `JourneyController`, `AuthController`, `EnvController` |

### Конфигурация и схема

| Файл | Что там |
|---|---|
| `src/main/resources/application.yml` | Все настройки и env-переменные (в т.ч. `app.proddb.*`) |
| `src/main/resources/db/migration/V*.sql` | Схема БД по шагам: V1 шаблоны, V2 пользователи, V3 цепочки, V4 аудит, V5–V6 слои процесса, V7 настройки панели, V8 единый справочник + очередь, V9 очистка очереди, V10 справочники форм, V11 роль супер-админа |
| `docker-compose.yml` / `docker-compose.server.yml` | Три контура / серверная надстройка с nginx |
| `nginx/crm-admin.conf` | Домен → только прод |
| `.env.example`, `DEPLOY.md` | Переменные и инструкция развёртывания |

### Фронтенд

| Файл | Что там |
|---|---|
| `static/index.html` | Вся панель одним файлом: оболочка (вафля, сайдбар, темы, переводы), формы мастера, SF-список, карточка шаблона (`sfd*`-функции), дашборд, стили |
| `static/api.js` | Клиент REST (`CRM.*`), фильтрация меню по правам (`applyNavAcl`), конфиг приложений |
| `static/wizard.js` | Логика форм мастера: справочники, цепочка дней, подсказки |
| `static/journeys.js` | Flow Builder: узлы, канва, предпросмотр материализации |
| `static/admin-users.js` | Экран «Управление доступом» |
| `static/settings/index.html` | Настроечная админка `/settings`, блок диагностики прод-БД |
| `static/combobox.js`, `drawflow.min.js` | Редактируемый список, библиотека схем |

### Частые правки — куда идти

| Задача | Файл |
|---|---|
| Поля формы мастера, значения по умолчанию | `static/index.html` (разметка форм) + `static/wizard.js` |
| Формулы `communication_name` / `campaign_name` | `static/index.html`: `updateComNameFromContext`, `computeCampaignName`; в карточке — `sfdComputeComname`, `sfdComputeCampaignName` |
| Правила кодов и обязательные поля прода | `service/UnifiedTemplateService.java` (`channelTable`, `prodDefaults`) |
| Что именно уезжает в прод | `service/TemplateStore.java` → `prodPayload` |
| Пополнить справочники | таблицы `dictionary.*` (SQL), новые значения появятся в формах сразу |
| Права и роли | `service/UserService.java` + `security/SecurityConfig.java` |
| Пункты меню и разделы | `static/index.html` (массив `NAV`) + `service/Sections.java` |
