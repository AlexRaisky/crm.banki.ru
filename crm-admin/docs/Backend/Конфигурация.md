# Конфигурация

Вся конфигурация — один `src/main/resources/application.yml` с тремя документами: базовый (общий для всех) + профили `docker` и `prod`. Почти каждое значение параметризовано env-переменной с дефолтом (`${VAR:default}`), поэтому одна и та же сборка запускается на трёх средах через docker-compose без пересборки (см. [[Среды и деплой]]).

## Точка входа

`src/main/java/ru/banki/crm/CrmAdminApplication.java` — минимальный `@SpringBootApplication`, никаких кастомных бинов; вся стартовая логика распределена по конфигурируемым компонентам (`SecurityConfig`, `AdminBootstrap` и т.д.).

## Базовый профиль (общий)

### spring.datasource / jpa

- `url = ${DB_URL:jdbc:postgresql://localhost:5432/crm}`, `username = ${DB_USER:crm}`, `password = ${DB_PASSWORD:crm}`.
- `jpa.open-in-view: false` — сессия Hibernate не тянется в рендеринг (чистый REST).
- `hibernate.ddl-auto: none` — схему приложение **никогда** не создаёт через Hibernate; это делает Flyway (docker) или она уже существует (prod).
- `hibernate.jdbc.time_zone: Europe/Moscow` — все timestamp'ы пишутся/читаются в московском времени, как в прод-БД.

### spring.flyway (база)

- `enabled: true`, `schemas: notice,callcenter,retention,arch,app`, `default-schema: app` (в `app` живёт таблица истории Flyway), `create-schemas: true`.
- Схемы `flow`, `tracker`, `scheduler`, `template`, `commapi` в списке нет — их создают сами миграции (`CREATE SCHEMA IF NOT EXISTS` в `V5__process_layer_b.sql` и `V6__flow_layer_a.sql`); список миграций — в [[Схема БД]].

### server

- `port: 8080` (внутри контейнера; наружу мапится compose-ом).
- `forward-headers-strategy: framework` — корректные схема/хост за реверс-прокси.
- `servlet.session.timeout: ${SESSION_TIMEOUT:7d}` — длинная сессия; после её истечения вход восстанавливает remember-me кука (см. [[Безопасность и RBAC]]).
- `servlet.session.cookie.name: ${SESSION_COOKIE:JSESSIONID}` — **своё имя куки на среду**: prod/preprod/test живут на одном хосте, и с одинаковым именем куки сред затирали бы друг друга.
- `error.include-message: always`, `include-binding-errors: always` — русские сообщения `ResponseStatusException` и bean-validation доезжают до SPA.

### springdoc

`swagger-ui.path: /swagger-ui.html` — интерактивная документация API (см. [[REST API]]).

## Профиль docker

Активируется `SPRING_PROFILES_ACTIVE=docker` (compose ставит его всем трём приложениям по умолчанию). Смысл профиля: **встроенная БД для local/dev/demo** — Flyway строит прод-идентичную схему и заливает демо-данные.

```yaml
spring.flyway:
  locations: classpath:db/migration,classpath:db/seed
  out-of-order: true
```

- К миграциям схемы (`db/migration`: V1–V6) добавляются сиды (`db/seed`: `V900__seed_dev.sql`, `V901__seed_journeys.sql`).
- **Почему `out-of-order: true`**: сиды заняли версии V900+. На уже поднятой dev-БД Flyway успел применить V900/V901, и любая новая схемная миграция (V3, V4, V5, …) оказывается «младше» максимально применённой версии — по умолчанию Flyway такое отвергает. `out-of-order` разрешает применять их задним числом. Это безопасно **только** для dev-БД этого профиля; на проде вопрос не стоит, там Flyway выключен вовсе.

## Профиль prod

Подключение к **существующей корпоративной** PostgreSQL: таблицы там уже есть, поэтому

```yaml
spring.flyway.enabled: false
app.audit.enabled: true
```

— никаких миграций, только работа поверх готовой схемы; аудит-GUC явно включён (прод-триггер `arch_log` настоящий). Обрати внимание: docker-compose в репозитории активирует профиль `docker` даже для контура «prod» (это локальная эмуляция трёх сред); профиль `prod` предназначен для развёртывания против реальной корпоративной БД.

## Значения по средам (docker-compose.yml)

Файл в корне repo описывает три пары db+app (postgres:16 + crm-admin:local):

| | prod | preprod | test |
|---|---|---|---|
| контейнеры | `crm-admin-{db,app}-prod` | `-preprod` | `-test` |
| порт приложения | `${APP_PORT:-8080}` | `${APP_PORT_PREPROD:-8081}` | `${APP_PORT_TEST:-8082}` |
| порт БД (наружу) | 5432 | 5433 | 5434 |
| том БД | `crm_db_data` (прежнее имя — данные прод-контура сохранены) | `crm_db_preprod` | `crm_db_test` |
| `APP_ENV` | `prod` | `preprod` | `test` |
| `FEATURES_DEV` | `false` | `false` | **`true`** — только здесь виден раздел «Цепочки» |
| `JOURNEYS_MOCK` | `${JOURNEYS_MOCK:-true}` | `${JOURNEYS_MOCK:-true}` | **`"false"`** — цепочки в БД, нужно для материализации (FK `journey_id`) |
| `SESSION_COOKIE` | `CRMSID_PROD` | `CRMSID_PREPROD` | `CRMSID_TEST` |
| `REMEMBER_COOKIE` | `crm-remember-prod` | `crm-remember-preprod` | `crm-remember-test` |
| `REMEMBER_ME_KEY` | `${REMEMBER_ME_KEY:-...}-prod` | `...-preprod` | `...-test` |

Общие для всех: `SPRING_PROFILES_ACTIVE=${SPRING_PROFILES_ACTIVE:-docker}`, `DB_URL=jdbc:postgresql://db-<среда>:5432/${DB_NAME:-crm}`, `DB_USER`/`DB_PASSWORD` (дефолт `crm`/`crm`), `ADMIN_EMAIL`/`ADMIN_PASSWORD`, `APP_EMAIL_DOMAIN` (пусто), `REMEMBER_ME_DAYS=30`, `SESSION_TIMEOUT=7d`. К ключу remember-me добавлен суффикс среды — токены одной среды не валидны в другой даже при общем базовом ключе. У db-сервисов healthcheck `pg_isready`; app-{preprod,test} ждут `app-prod` (`service_started`) — тот собирает общий образ `crm-admin:local`.

Детальная процедура деплоя — [[Среды и деплой]].

## EnvController

`src/main/java/ru/banki/crm/web/EnvController.java`: GET `/api/env` → record `EnvDto(String name, boolean devFeatures)` из `app.env.name` / `app.features.dev`. Доступен любому аутентифицированному; SPA по нему красит бейдж среды в шапке и решает, показывать ли dev-разделы NAV (см. [[Обзор фронтенда]]). Внимание: это UI-переключатель — API цепочек (`/api/journeys`, `/api/flow`) закрыт RBAC-ом, но не флагом `FEATURES_DEV`.

## Как значения попадают в код

Не через `@ConfigurationProperties`, а точечными `@Value` в компонентах:

- `SecurityConfig` — `app.remember-me.*`, `server.servlet.session.cookie.name`;
- `UserService` — `app.email-domain`;
- `AdminBootstrap` — `app.admin.email` / `app.admin.password`;
- `AuditContext` — `app.audit.enabled`;
- `AdminLogService` — все `app.tables.*`;
- `EnvController` — `app.env.name`, `app.features.dev`;
- `MockJourneyService` / `DbJourneyService` — выбор по `app.journeys.mock` через `@ConditionalOnProperty` (см. [[Обзор бэкенда]]).
