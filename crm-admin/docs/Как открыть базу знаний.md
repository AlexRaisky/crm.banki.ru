# Как открыть базу знаний

## О чём эта заметка

Документация панели — это не набор файлов рядом с кодом, а связанное хранилище: заметки ссылаются друг на друга, собраны в разделы и снабжены тегами. Читать его можно как угодно — хоть в GitHub, хоть текстовым редактором, — но задумано оно под [Obsidian](https://obsidian.md): там работают переходы по ссылкам, обратные ссылки, поиск по всему хранилищу и граф связей.

Эта заметка — про то, как открыть хранилище, как оно устроено и по каким правилам в него пишут.

## Открыть за две минуты

1. Поставить Obsidian (бесплатный, есть под Windows, macOS и Linux).
2. В стартовом окне выбрать **Open folder as vault**.
3. Указать папку `crm-admin/docs` в клоне репозитория. **Именно `docs`, а не корень проекта** — иначе в хранилище попадут исходники, а граф связей превратится в кашу из тысяч файлов.

Всё. Настройки уже лежат в репозитории, так что вид, тема и включённые плагины у всех одинаковые.

Начинать читать — с [[Home]] или [[Оглавление]]. Новому человеку — с [[Путь новичка]].

## Что уже настроено

Конфигурация хранится в `docs/.obsidian` и едет вместе с репозиторием:

| файл | что задаёт |
|---|---|
| `app.json` | ссылки в формате `[[короткое имя]]`, переименование заметки чинит ссылки на неё автоматически, файлы открываются в режиме чтения |
| `core-plugins.json` | что включено: поиск, граф, обратные ссылки, оглавление, теги, закладки |
| `appearance.json` | тёмная тема, акцент — цвет панели |
| `graph.json` | раскраска графа по разделам: бэкенд, фронтенд, база, архитектура, API |

Ничего дополнительно ставить не нужно: сторонних плагинов в хранилище нет намеренно — база знаний должна открываться у любого, кто клонировал репозиторий, без подготовки.

## Как устроено хранилище

```
docs/
├── Home.md              — точка входа
├── Оглавление.md        — полный список заметок
├── Путь новичка.md      — маршрут для того, кто пришёл впервые
├── Шпаргалка.md         — команды одной строкой
├── Глоссарий.md         — незнакомые слова
├── Флоу системы.md      — как всё работает целиком
├── Architecture/        — контуры, деплой, RBAC, технологии
├── Backend/             — сервисы, переливы, интеграции
├── Frontend/            — экраны, оболочка, формы
├── Database/            — схемы, слои A и B, справочники
└── API/                 — REST-ручки
```

У каждой заметки в шапке стоят теги (`process`, `backend`, `howto` и прочие) — по ним удобно собирать подборки через поиск `tag:#backend`.

## Правила, по которым пишут заметки

- **Ссылка вместо пересказа.** Если тема раскрыта в соседней заметке — ставится `[[ссылка]]`, а не короткий пересказ, который через месяц разойдётся с оригиналом.
- **Заголовок — предложение, а не ярлык.** Заметка отвечает на вопрос, а не «описывает раздел».
- **Почему важнее чем что.** Что делает код, видно из кода. В заметку идёт то, чего в коде не прочитать: почему сделано так, что пробовали до этого и чем это кончилось.
- **Название файла — часть адреса.** Переименование ломает ссылки у всех; Obsidian чинит их автоматически, но только если переименовывать внутри него, а не в проводнике.
- **Правишь код — правь заметку.** Документация, разошедшаяся с кодом, вреднее её отсутствия: ей верят.

## Что не попадает в репозиторий

`docs/.obsidian/.gitignore` исключает личное: раскладку панелей (`workspace.json`), историю, кэш поиска, установленные локально плагины и темы. Иначе каждый открытый коллегой файл приезжал бы конфликтом слияния.

Общими остаются только настройки, одинаковые для всех: формат ссылок, набор ядровых плагинов, тема и раскраска графа.

## Если Obsidian нет

Заметки — обычный Markdown, они читаются где угодно. Потеряются только переходы по `[[ссылкам]]`, граф и обратные ссылки; текст останется тем же. В GitHub такие ссылки не кликаются — это ожидаемо, хранилище рассчитано на Obsidian.
