# Оболочка панели (shell)

Оболочка SPA устроена по образцу **Salesforce Lightning**: глобальная шапка с App Launcher-«вафлей», левый сайдбар разделов с всплывающим меню 2-го уровня, обзорные страницы групп, тема light/dark/system и i18n RU/EN. Горизонтального верхнего меню нет.

Код — `js/shell.js` (`NAV`, `ICONS`, словари i18n, `renderNav`, `openSection`, `applyTheme`, `applyLang`, `store`, виджеты Главной, «Загруженные инструменты»), разметка — `index.html`, стили — `css/shell.css`. RBAC-фильтрацию поверх выполняет `applyNavAcl()` из [Клиент API (api.js)](Клиент%20API%20(api.js).md).

Всё состояние оболочки лежит в `localStorage` под префиксом `crmpanel:` — доступ через хелпер `store.get/set` (`js/shell.js:595`).

## Глобальная шапка

Слева направо: логотип **CRM Team** → кнопка-«вафля» `#waffleBtn` → название текущего приложения → бейдж среды `.env-pill` (появляется после ответа `/api/env`) → «хлебная крошка» «родитель › раздел».

Справа: «Настроить главную» (видна только на Главной), **шестерёнка** — ссылка на `/settings`, скрыта по умолчанию и показывается только админам, и блок учётки: почта и три кнопки.

| Кнопка | Что делает |
|---|---|
| **Вид** | `openPrefsDialog()` (`js/shell.js:845`) — диалог «Общие параметры»: тема и язык **для своей учётки** |
| **Пароль** | `openPwdDialog()` — смена собственного пароля, см. [Управление доступом и вход](Управление%20доступом%20и%20вход.md) |
| **Выйти** | `CRM.logout()` |

Кнопка «Вид» появилась потому, что раньше тему и язык можно было выбрать только в `/settings`, то есть фактически только администратору. Теперь это личная настройка: `prefsThemeChange` / `prefsLangChange` пишут в те же ключи `crmpanel:theme` и `crmpanel:lang` и применяют изменение сразу (`js/shell.js:855`).

Кнопки **иконочные на узких экранах**: с 1100 px и ниже `shell.css` скрывает подписи (а заодно почту и «Настроить главную») — три текстовые кнопки не помещались в шапку и вызывали горизонтальный скролл страницы. Атрибут `data-i18n` стоит на внутреннем `<span>`, а не на кнопке: `translateStatic()` пишет в `textContent` и стёр бы иконку.

Остальные ступени адаптива: **1000 px** — из крошки пропадают родитель и стрелка; **760 px** — крошка скрывается целиком, сетка Главной становится одноколоночной, сайдбар переходит в `position: fixed`, прячется словесный логотип; **700 px** — скрывается название приложения и дожимаются отступы (иначе на 375 px не хватало пары пикселей).

## App Launcher: приложения

По клику на вафлю открывается панель со списком **пяти приложений** (`APPS`, `js/shell.js:606`):

| Приложение | Подпись |
|---|---|
| Администрирование | Полный набор разделов панели |
| Аналитика | Дашборды, статистика и отклонения |
| Маркетинг | Коммуникации, шаблоны и кампании |
| Бизнес | Бизнес-инструменты и отчётность |
| Контактный центр | Управление настройками контактных центров |

Текущее приложение — `crmpanel:app` (по умолчанию «Администрирование»). Набор разделов задаёт конфиг `crmpanel:appSections` (`{"Приложение": ["home", …]}`; отсутствие записи = все разделы): `appAllows(sid)` фильтрует пункты 1-го уровня (`js/shell.js:621`), `childVisible(k)` — детей с полем `appOnly`. Сейчас `appOnly` стоит только у «Тепловой карты» (приложение «Маркетинг»), и `updateAppSpecific()` управляет её карточкой на обзорной странице (`js/shell.js:677`).

**Истина конфига — в БД**, `app.panel_settings`, ключ `appSections`; редактируется в [Страница настроек (settings)](Страница%20настроек%20(settings).md), в localStorage только зеркалится.

`setApp(id)` (`js/shell.js:681`) перерисовывает launcher и сайдбар и, если открытый раздел в новом приложении недоступен, уводит на Главную, а если недоступен только подраздел — на обзорную страницу группы.

## Сайдбар и дерево NAV

Массив `NAV` (`js/shell.js:12`) двухуровневый: элемент с `children` — группа (по наведению показывает flyout, по клику открывает **обзорную страницу**); дочерний элемент указывает `view` — id секции. Комментарий в коде: «id разделов НЕ менять: на них завязан RBAC (me.sections)».

| 1-й уровень | Дети | Особенности |
|---|---|---|
| `home` Главная (`js/shell.js:17`) | — | `noAcl:true` |
| `comms` Управление коммуникациями (`js/shell.js:18`) | `onelink` · `admin` Мастер коммуникаций (`adminMode:"wizard"`) · `viewer` Просмотр настроек (`aclSection:"admin"`) · `srcbuilder` · `promo` · `abtests` · `heatmap` (`appOnly:["Маркетинг"]`) | **«Список шаблонов» отсюда убран** — переехал в `entities` как `ent-template` |
| `entities` Сущности (`js/shell.js:45`) | **динамические** — по пункту на сущность схемы | `children` заполняет `entSyncNav()`, `adminOnly` вычисляемый — см. [Сущности](Сущности.md) |
| `reports` Отчёты (`js/shell.js:49`) | `rep-planfact` · `rep-matrix` · `rep-leadgen` · `rep-smscheck` · `rep-demo` | у первых трёх поле `report` — какую книгу Tableau открыть |
| `dash` Дашборд (`js/shell.js:59`) | `dashboard` Общая статистика (`adminMode:"dashboard"`) · `deviations` Панель отклонений | |
| `monitoring` Мониторинг (`js/shell.js:63`) | `mon-campaigns` Базовая работа кампаний | |
| `uploads` Загруженные инструменты (`js/shell.js:66`) | динамические: «Загрузить инструмент» + по пункту на инструмент, все `noAcl` | |
| `journeys` Цепочки (`js/shell.js:67`) | — | `adminOnly:true` |

Три уточнения, которых легко не заметить:

- **«Управление доступом» из `NAV` убрано** — экран переехал в `/settings`. `openSection()` это учитывает: id, которого нет ни в `NAV`, ни среди детей, уводит на Главную.
- **Ограничения по среде больше нет ни у одного пункта.** Механика `envs:[...]` / `data-envs` в оболочке и `api.js` жива, но поле сейчас нигде не задано (`js/shell.js:71`): «Цепочки» закрыты ролью, а не средой. См. [Среды и деплой](../Architecture/Среды%20и%20деплой.md).
- **`aclSection` остался только у «Просмотра настроек»** (`viewer` → `admin`, `js/shell.js:25`) и у динамического `ent-template` (→ `templates`). У детей «Отчётов» и «Мониторинга» он убран в V29: id пункта и есть секция, доступ выдаётся по каждому отчёту отдельно ([Безопасность и RBAC](../Architecture/Безопасность%20и%20RBAC.md)). `noAcl` сейчас стоит у «Главной» и у динамических детей — «Загруженных инструментов» и сущностей.

`renderNav()` строит пункты, вешает data-атрибуты ACL-контракта и в конце сам зовёт `window.applyNavAcl()` — контракт разобран в [Клиент API (api.js)](Клиент%20API%20(api.js).md). Сайдбар сворачивается кнопкой `#collapseBtn` (`crmpanel:sidebarCollapsed`).

**Flyout 2-го уровня** появляется по наведению на группу и убирается с задержкой 200 мс. Список детей проходит через `orderedChildren` (порядок), `childVisible` (appOnly) и `aclAllows` (`js/shell.js:698`) — клиентское зеркало правил `applyNavAcl` для списков, которые строятся динамически и потому не имеют DOM с data-атрибутами.

### Очерёдность подразделов

Порядок детей внутри `comms` / `reports` / `dash` / `monitoring` настраивается в `/settings` и хранится в `crmpanel:subOrder`. Применяется в двух местах: `orderedChildren(s)` — к flyout, `applySubOrder()` — к карточкам обзорных страниц. Не перечисленные в конфиге пункты уезжают в конец в исходном порядке. Открытая вкладка панели подхватывает изменение по событию `storage` (`js/shell.js:583`).

### openSection(sid, cid)

Единая точка навигации (`js/shell.js:861`). По шагам:

1. **Совместимость со старой плоской навигацией**: `openSection('admin')` (например, из `journeys.js`) находит родителя и превращается в `openSection('comms','admin')`. Неизвестный id → Главная.
2. Проверки `appAllows(sid)` и `sectionAllowed(s)` — при отказе уводит на Главную.
3. Разбор цели: у группы без `cid` — обзорная страница; недоступный ребёнок сбрасывается в обзор; у `uploads` цель считает `uploadChildren()`.
4. Переключение `.view` / `.nav-item` и хуки живого приложения (`js/shell.js:897`): `monBack()` при входе в мониторинг, `setAdminMode(...)` для `#sec-admin`, `rpEmbedOpen(report)` для отчётов Tableau, `entOpen(entity)` и `entRenderOverview()` для сущностей, `scInit()` для «ЧЕК СМС траффик», `initJourneysSection()` для «Цепочек», отложенное лечение графиков в «Панели отклонений».
5. `trackRecent`, `renderSectionHero`, `renderPageCrumb`, `document.title`, показ «Настроить главную» и запись `crmpanel:lastSection`.

Последний раздел восстанавливает `js/boot.js` — **только после ответа `/api/env`** (иначе разделы, ограниченные средой, открылись бы до того, как выяснится, что их быть не должно). Там же живёт миграция старого строкового формата `lastSection` в пару `{sid, cid}` — включая перенос `templates` в `entities/ent-template`.

### Заголовок раздела

Два независимых механизма:

- `renderPageCrumb` — крошка в шапке «родитель › раздел»; для загруженного инструмента заголовком становится его имя и не переводится;
- `renderSectionHero` — «герой» раздела (надзаголовок, `h1`, описание) из карты `SEC_HERO` (`js/shell.js:932`), семь ключей вида `sid:cid`. Раздел, у которого **уже есть собственный `h1` в разметке** (OneLink, Конструктор source, Отклонения, Промо, А/Б тесты, отчёты), героя не получает и ранее добавленный удаляется (`js/shell.js:957`) — второй заголовок на странице не нужен.

## Обзорные страницы групп

`view-comms-overview` / `view-entities-overview` / `view-reports-overview` / `view-dash-overview` / `view-mon-overview` — сетки карточек с описанием подраздела и ссылкой «Открыть →». Каждая карточка несёт `data-nav-ref`, и `applyNavAcl` скрывает её синхронно с правами соответствующего пункта NAV. Карточка тепловой карты скрыта всегда, кроме приложения «Маркетинг».

Сетка сущностей рисуется не разметкой, а `entRenderOverview()` из `js/entities.js`.

## Загруженные инструменты

Пользователь загружает **свои HTML-страницы** внутрь панели. Файлы хранятся в `crmpanel:uploadedTools` (`{id, name, html, ts}`); лимит хранилища браузера ~5 МБ — при переполнении показывается alert с просьбой удалить неиспользуемые. Загрузка — drag&drop или выбор файла, название берётся из поля либо распознаётся из `<title>` / `<h1>`.

Инструмент появляется карточкой в обзоре и пунктом во flyout (`uploadChildren()`, `js/shell.js:1052`), открывается во встроенном фрейме **в исходном оформлении** — без адаптации под тему панели, — с масштабированием под размер окна; на странице есть «Переименовать» и «Удалить». Тем же хранилищем управляет `/settings`.

## Тема light / dark / system

`applyTheme()` (`js/shell.js:548`): настройка в `crmpanel:theme` (`dark` по умолчанию, `light`, `system` — по `prefers-color-scheme`); светлая тема включается классом **`html.theme-light`** на корневом элементе.

Светлая тема **покрывает не всё**. Набор переменных переопределяется ровно для четырёх корней — `body`, `#sec-admin`, `#sec-onelink`, `#sec-deviations` (`css/shell.css:26`). Причина не в лени: эти три секции **переобъявляют собственные тёмные переменные внутри своего `@scope`** и потому не наследуют их от `body`, а `#sec-admin` вдобавок содержит прямые хардкоды фона и шрифта. Остальные секции пользуются `var(--…)` без собственных объявлений и получают светлую тему автоматически.

Поверх этого — точечная добивка (`css/shell.css:499`) для тёмных фонов, не сидящих на переменных: канва цепочек и модалки Drawflow, тулбар загруженных инструментов, VK-бейджи, «консольные» подложки OneLink и конструктора source, списки `select`, `color-scheme` для `input[type=date]`, тултипы.

Тема реагирует на смену системной и на изменение в другой вкладке (событие `storage`). Выбирается кнопкой «Вид» в шапке или в `/settings` → «Общие параметры» — оба пишут в один ключ.

### Подсказки полей: два механизма

- **`#fieldHelpPopup`** — общий `position:fixed`-попап; позицию считает `showFieldHelp(el)` и **держит в пределах экрана**: не влезает снизу — показывается над значком, упирается в край — прижимается с отступом. Им пользуются все значки «Мастера коммуникаций».
- **CSS-тултип `.info > .tip`** — статические подсказки в разметке OneLink Builder, с разметкой внутри. Абсолютный блок по центру значка; сам про край экрана не знает, поэтому `clampTip()` в `shell.js` на `mouseover` / `focusin` считает сдвиг и кладёт его в `--tip-dx` — CSS двигает на него тултип и на столько же в обратную сторону стрелку, чтобы она продолжала указывать на значок.

Раньше подсказки полей тоже строились как `.tip`, и у левых полей (например, фильтр «Канал» в списке шаблонов) тултип уезжал на сайдбар и перекрывал шапку раздела — отсюда перевод этих значков на попап.

## i18n RU / EN

Язык — `crmpanel:lang` (`ru` по умолчанию), применяется `applyLang(rerender)` (`js/shell.js:554`):

- словарь `I18N_EN` (строка RU → строка EN, `js/shell.js:110` и три дополняющих `Object.assign` — по промо, отчётам и сущностям) и `I18N_HTML` (токены заголовков с градиентной разметкой, `js/shell.js:500`); функции `t(s)` и `tt(token)`;
- статичная разметка переводится `translateStatic()` по атрибутам `data-i18n` (текст), `data-i18n-html` (токен), `data-i18n-ph` (placeholder);
- динамика: `applyLang(true)` перерисовывает launcher, сайдбар и виджеты Главной и дёргает хуки разделов, если они объявлены — `sbUpdate()`, `translateAdminChrome()`, `promoRender()`, `rpRender()`, `entRenderOverview()`, `entRender()`, `renderUploads()`, плюс заново рисует героя раздела и крошку;
- **осознанно не переводятся**: подсказки полей мастера и сообщения `alert` / `confirm` / `prompt` — остаются по-русски;
- смена языка в другой вкладке подхватывается событием `storage`; у `/settings` собственный мини-словарь на том же ключе.

Переводится по существу только оболочка: сайдбар, вафля, обзорные страницы, Главная и обвязка разделов. Данные не переводятся никогда.

## Главная (view-home)

Настраиваемая сетка виджетов (`WIDGETS`, `js/shell.js:1235`):

| Виджет | Что показывает |
|---|---|
| `summary` «Сводка по коммуникациям» | четыре KPI-плитки — **демо-числа** |
| `tasks` «Мои задачи» | to-do в `crmpanel:tasks` |
| `recent` «Недавно использованные инструменты» | последние открытые разделы (`trackRecent`, `crmpanel:recent`) |
| `quicklinks` «Быстрые ссылки» | листья навигации с учётом приложения и `aclAllows` |
| `status` «Статусы систем» | **демо-данные для MVP** |

Раскладка — `crmpanel:layout`, по умолчанию `summary / tasks / recent / quicklinks`; «Статусы систем» в дефолт не входит и добавляется чипом. Режим настройки включает кнопка «Настроить главную»: виджеты можно перетаскивать, удалять крестиком и добавлять чипами из строки под сеткой.
