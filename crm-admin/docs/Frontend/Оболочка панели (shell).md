# Оболочка панели (shell)

Оболочка SPA устроена по образцу **Salesforce Lightning**: глобальная шапка с App Launcher-«вафлей», левый сайдбар разделов с всплывающим меню 2-го уровня, обзорные страницы групп, тема light/dark/system и i18n RU/EN. Горизонтального верхнего меню нет.

Код оболочки — `src/main/resources/static/js/shell.js` (`NAV`, `ICONS`, словари i18n, `renderNav`, `openSection`, `applyTheme`, `applyLang`, `store`, виджеты Главной, «Загруженные инструменты»), разметка — `index.html`, стили — `css/shell.css`. RBAC-фильтрацию поверх выполняет `applyNavAcl()` из `api.js` (см. [[Обзор фронтенда]]).

Всё состояние оболочки лежит в `localStorage` под префиксом `crmpanel:` — доступ через хелпер `store.get/set`.

## Глобальная шапка (gheader)

Слева направо: логотип **CRM Team** → кнопка-«вафля» `#waffleBtn` (App Launcher) → название текущего приложения `#appName` → бейдж среды `.env-pill` (добавляется после ответа `CRM.envReady`, текст — имя среды капсом) → «хлебная крошка» `#pageCrumb` («родитель › раздел»).

Справа (`.gheader-actions`): кнопка «Настроить главную» (`#homeActions`, видна только на Главной), **шестерёнка `#settingsLink`** — ссылка на настроечную админку `/settings`, скрыта по умолчанию и показывается только админам, и блок учётки `#userBox`.

### Блок учётки: почта + три кнопки

`#userEmail` (подпись заполняет `applyNavAcl`) и три кнопки `.ub-btn`:

| Кнопка | Что делает |
|---|---|
| **Вид** | `openPrefsDialog()` — диалог «Общие параметры»: тема и язык **для своей учётки** |
| **Пароль** | `openPwdDialog()` — смена собственного пароля, см. [[Управление доступом и вход]] |
| **Выйти** | `CRM.logout()` |

Кнопка «Вид» появилась 30.07.2026: раньше тему и язык можно было выбрать только в `/settings`, то есть фактически только администратору. Теперь это личная настройка любого пользователя — `prefsThemeChange` / `prefsLangChange` пишут в те же ключи `crmpanel:theme` и `crmpanel:lang` и применяют изменение сразу, без прав администратора.

Кнопки **иконочные на узких экранах**: с 1100 px и ниже `css/shell.css` скрывает `.ub-btn span` (а заодно `.user-email` и «Настроить главную») — три текстовые кнопки не помещались в шапку и вызывали горизонтальный скролл страницы. Атрибут `data-i18n` стоит на внутреннем `<span>`, а не на кнопке: `translateStatic()` пишет в `textContent` и стёр бы иконку.

Остальные ступени адаптива шапки и оболочки в `shell.css`: **1000 px** — из крошки пропадают родитель и стрелка; **760 px** — крошка скрывается целиком, сетка Главной становится одноколоночной, сайдбар переходит в `position: fixed`, прячется словесный логотип; **700 px** — скрывается название приложения и дожимаются отступы шапки и кнопок (иначе на 375 px не хватало пары пикселей).

## App Launcher: приложения

По клику на вафлю открывается панель `#launcher` со списком **пяти приложений** (константа `APPS`):

| Приложение | Подпись |
|---|---|
| Администрирование | Полный набор разделов панели |
| Аналитика | Дашборды, статистика и отклонения |
| Маркетинг | Коммуникации, шаблоны и кампании |
| Бизнес | Бизнес-инструменты и отчётность |
| Контактный центр | Управление настройками контактных центров |

Текущее приложение — `crmpanel:app` (по умолчанию «Администрирование»). Набор разделов приложения задаёт конфиг `crmpanel:appSections` (`{ "Приложение": ["home", …] }`; `null` или отсутствие записи = все разделы): `allowedSections()` / `appAllows(sid)` фильтруют пункты 1-го уровня, `childVisible(k)` — детей с полем `appOnly` (сейчас так ограничена только «Тепловая карта» — приложение «Маркетинг»; `updateAppSpecific()` управляет и её карточкой `#ovHeatmapCard` на обзорной странице).

**Истина конфига — в БД** (`app.panel_settings`, ключ `appSections`): `syncAppSections()` в `api.js` при загрузке тянет `GET /api/panel-settings/appSections`, зеркалит значение в localStorage и перерисовывает сайдбар; редактируется конфиг в `/settings` → «Приложения и разделы».

`setApp(id)` перерисовывает launcher и сайдбар и, если открытый раздел в новом приложении недоступен, уводит на Главную, а если недоступен только подраздел — на обзорную страницу группы.

## Сайдбар и дерево NAV

Массив `NAV` (`js/shell.js`) двухуровневый: элемент с `children` — группа (по наведению показывает flyout, по клику открывает **обзорную страницу** `overviewView`); дочерний элемент указывает `view` (id секции) и, для админки, `adminMode`. Комментарий в коде: «id разделов НЕ менять: на них завязан RBAC (me.sections)».

| 1-й уровень | 2-й уровень (children) | Особенности |
|---|---|---|
| `home` Главная | — | `view-home`, виджеты |
| `comms` Управление коммуникациями | `onelink` OneLink Builder · `admin` Мастер коммуникаций (`adminMode:"wizard"`) · `templates` Список шаблонов (`list`) · `viewer` Просмотр настроек (`view`, `aclSection:"admin"`) · `srcbuilder` Конструктор source · `promo` Планирование промо (`noAcl`) · `heatmap` Тепловая карта (`appOnly:["Маркетинг"]`) | обзор `view-comms-overview` |
| `reports` Отчёты | `rep-planfact` Plan-Fact · `rep-matrix` CRM Matrix · `rep-leadgen` CRM Leadgen · `rep-smscheck` **ЧЕК СМС траффик** · `rep-demo` Пример визуализации отчёта | обзор `view-reports-overview`; у всех детей `aclSection:"reports"` — единое право на весь раздел |
| `dash` Дашборд | `dashboard` Общая статистика (`adminMode:"dashboard"`) · `deviations` Панель отклонений | обзор `view-dash-overview` |
| `monitoring` Мониторинг | `mon-campaigns` Базовая работа кампаний (`aclSection:"monitoring"`) | обзор `view-mon-overview` |
| `uploads` Загруженные инструменты | динамические: «Загрузить инструмент» + по пункту на инструмент | `view-uploads` |
| `journeys` Цепочки | — | `adminOnly:true` |

Три уточнения, которых легко не заметить:

- **«Управление доступом» из `NAV` убрано** — экран переехал в `/settings` (см. [[Управление доступом и вход]]). `openSection()` это учитывает: id, которого нет ни в `NAV`, ни среди детей, уводит на Главную.
- **«Цепочки» больше не ограничены средой.** Механика `envs:[...]` / `data-envs` в оболочке и `api.js` осталась, но **ни один пункт NAV сейчас `envs` не задаёт**: раздел закрыт только ролью (`adminOnly`). См. [[Flow Builder (цепочки)]] и [[Среды и деплой]].
- `noAcl` сейчас стоит **только** у «Планирования промо» и у динамических детей «Загруженных инструментов». Соседний раздел «А/Б тесты» (`abtests`, [[АБ тесты]]) заведён уже правильно — гейтится по `me.sections` как обычный. Остальные пункты, включая `srcbuilder`, `mon-campaigns` и `uploads`, фильтруются по `me.sections` как обычные разделы. У промо это уже пережиток: комментарий в `NAV` обещает снять `noAcl`, «как таблица переедет на сервер», а она **уже переехала** — раздел работает через `/api/promo/plan` ([[Планирование промо]]).

`renderNav()` строит пункты `.nav-item`, вешает data-атрибуты ACL-контракта (см. ниже) и в конце сам зовёт `window.applyNavAcl()`. Сайдбар сворачивается кнопкой `#collapseBtn` (`crmpanel:sidebarCollapsed`).

**Flyout 2-го уровня** (`#flyout`) появляется по наведению на группу и убирается с задержкой 200 мс. Список детей проходит через `orderedChildren` (порядок), `childVisible` (appOnly) и `aclAllows` — клиентское зеркало правил `applyNavAcl` для динамически строящихся списков (flyout, «Быстрые ссылки» на Главной).

### Очерёдность подразделов

Порядок детей внутри групп `comms` / `reports` / `dash` настраивается в `/settings` → «Приложения и разделы» → «Очерёдность подразделов» и хранится в `crmpanel:subOrder` (`{ comms:[ids…], … }`). Применяется в двух местах: `orderedChildren(s)` — к flyout, `applySubOrder()` — к карточкам обзорных страниц (переставляет `.ov-card` по `data-nav-ref`). Не перечисленные в конфиге пункты уезжают в конец в исходном порядке. Открытая вкладка панели подхватывает изменение по событию `storage`.

### openSection(sid, cid)

Единая точка навигации. Что делает по шагам:

1. **Совместимость со старой плоской навигацией**: `openSection('admin')` (например, из `journeys.js`) находит родителя и превращается в `openSection('comms','admin')`. Неизвестный id → Главная.
2. Проверки `appAllows(sid)` и `sectionAllowed(s)` (env-гейтинг) — при отказе уводит на Главную.
3. Разбор цели: у группы без `cid` — обзорная страница; недоступный ребёнок (по `childVisible` / `aclAllows`) сбрасывается в обзор; у `uploads` цель считает `uploadChildren()`.
4. Переключение `.view` / `.nav-item` и хуки живого приложения: `monBack()` при входе в мониторинг, `setAdminMode(adminMode)` для `#sec-admin`, `rpEmbedOpen(report)` для отчётов Tableau, `scInit()` для «ЧЕК СМС траффик», `initJourneysSection()` для «Цепочек», отложенное лечение графиков Chart.js в «Панели отклонений» (созданные в скрытой секции, они получают нулевой размер, поэтому при первом показе пересоздаются через `renderAll()`; `setTimeout`, а не `requestAnimationFrame`, — rAF не срабатывает в фоновых вкладках).
5. `trackRecent`, `renderSectionHero`, `renderPageCrumb`, `document.title`, показ/скрытие «Настроить главную» и запись `crmpanel:lastSection` (`{sid, cid}`).

Последний раздел восстанавливает `js/boot.js` — **только после ответа `/api/env`** (иначе разделы, ограниченные средой, открылись бы до того, как выяснится, что их быть не должно). Там же живёт миграция старого строкового формата `lastSection` в пару `{sid, cid}`.

### Заголовок раздела

Два независимых механизма:

- `renderPageCrumb(s, cid, label)` — крошка в шапке: «родитель › раздел»; для загруженного инструмента заголовком становится его имя и не переводится;
- `renderSectionHero(viewId, sid, cid)` — «герой» раздела (надзаголовок, `h1`, описание) из карты `SEC_HERO`. Раздел, у которого уже есть собственный `h1` в разметке (OneLink, Конструктор source, Отклонения, Промо), героя не получает — второй заголовок не добавляется.

## Обзорные страницы групп

`view-comms-overview` / `view-reports-overview` / `view-dash-overview` / `view-mon-overview` — сетки карточек `.ov-card` с описанием подраздела и ссылкой «Открыть →». Каждая карточка несёт `data-nav-ref="<id>"`, и `applyNavAcl` скрывает её синхронно с правами соответствующего пункта NAV; карточка «Просмотр настроек» дополнительно несёт `data-acl-section="admin"`, карточки отчётов — `data-acl-section="reports"`, «Планирование промо» — `data-no-acl="1"`. Карточка тепловой карты `#ovHeatmapCard` скрыта всегда, кроме приложения «Маркетинг» (`updateAppSpecific`).

## Мониторинг (заглушки)

Раздел «Мониторинг» → «Базовая работа кампаний» (`view-mon-campaigns`): пять карточек контрольных точек жизненного цикла кампании — **Работа отбора базы · Наличие поступления событий · Наличие отправок коммуникаций · Наличие доставок · Дублирование отправок**. Клик открывает `monDetail(title)` — заглушку «Статистика в разработке» с кнопкой «← К блокам мониторинга» (`monBack`). Второй набор блоков мониторинга («Работа с партнёрами») живёт в `/settings` и тоже заглушен.

## Загруженные инструменты

Раздел `uploads`: пользователь загружает **свои HTML-страницы** внутрь панели. Файлы хранятся в `localStorage` (`crmpanel:uploadedTools`, объекты `{id, name, html, ts}`); лимит хранилища браузера ~5 МБ — при переполнении `saveTools()` показывает alert с просьбой удалить неиспользуемые инструменты. Загрузка — drag&drop или выбор файла (`uploadFormHtml` / `wireUploadForm`), название берётся из поля либо распознаётся из `<title>` / `<h1>` (`detectToolName`).

Инструмент появляется карточкой в обзоре раздела и пунктом во flyout (`uploadChildren()` — «Загрузить инструмент» плюс по пункту на файл, все с `noAcl`), открывается во встроенном фрейме **в исходном оформлении** (без адаптации под тему панели) с масштабированием под размер окна; на странице инструмента есть «Переименовать» и «Удалить». Управлять теми же инструментами можно из `/settings` → «Загруженные инструменты» (то же хранилище браузера).

## Тема light / dark / system

`applyTheme()`: настройка в `crmpanel:theme` (`dark` по умолчанию, `light`, `system` — по `prefers-color-scheme`); светлая тема включается классом **`html.theme-light`** на корневом элементе.

Светлая тема **покрывает не всё**. Набор переменных переопределяется ровно для четырёх корней — `body`, `#sec-admin`, `#sec-onelink`, `#sec-deviations` (в `shell.css` это прямо оговорено комментарием: разделы писались под тёмную тему). Остальные `@scope`-секции — `#sec-promo`, `#sec-srcbuilder`, `#view-reports`, `#view-report-embed` — своих светлых переменных не получают, для них есть только точечные патчи (селекты, `input[type=date]`, отдельные бейджи). Отдельно доопределены канва цепочек `#jrCanvas` и модалки Drawflow, попап подсказок полей `#fieldHelpPopup`, шапка и карточки оболочки.

Тема реагирует на смену системной (`matchMedia("(prefers-color-scheme: light)")`) и на изменение в другой вкладке (событие `storage`). Выбирается кнопкой «Вид» в шапке или в `/settings` → «Общие параметры».


### Подсказки полей: два механизма

- **`#fieldHelpPopup`** — общий `position:fixed`-попап, позицию считает `showFieldHelp(el)` по `data-help` значка и **держит в пределах экрана** (не влезает снизу — показывается над значком, упирается в край — прижимается с отступом 10px). Им пользуются все значки «Мастера коммуникаций»: и карточка шаблона (`sfdHintHtml`), и значки, которые вешает `initFieldHelp` / `makeInfoIcon` на поля форм, фильтры списка и группы флагов.
- **CSS-тултип `.info > .tip`** — статические подсказки в разметке OneLink Builder (11 штук, с разметкой внутри: `<b>`, `<code>`). Абсолютный блок шириной 250px по центру значка; сам про край экрана не знает, поэтому `clampTip()` в `shell.js` на `mouseover` / `focusin` считает сдвиг и кладёт его в `--tip-dx` — CSS двигает на него тултип и на столько же в обратную сторону стрелку `::after`, чтобы она продолжала указывать на значок.

Раньше `makeInfoIcon` тоже строил `.tip`, и у левых полей (например, фильтр «Канал» в списке шаблонов) тултип уезжал на сайдбар и перекрывал шапку раздела — отсюда перевод этих значков на попап.

## i18n RU / EN

Язык — `crmpanel:lang` (`ru` по умолчанию), применяется `applyLang(rerender)`:

- словарь `I18N_EN` (строка RU → строка EN) и `I18N_HTML` (токены для заголовков с градиентной разметкой, напр. `h1_comms`, `h1_promo`, `h1_reports_ov`); функции `t(s)` и `tt(token)`;
- статичная разметка переводится `translateStatic()` по атрибутам `data-i18n` (текст), `data-i18n-html` (токен), `data-i18n-ph` (placeholder);
- динамика: `applyLang(true)` перерисовывает launcher, сайдбар и виджеты Главной и дёргает хуки разделов, если они объявлены — `translateAdminChrome()`, `promoRender()`, `rpRender()`, `sbUpdate()`, `renderUploads()`, плюс заново рисует героя раздела и крошку;
- **осознанно не переводятся**: подсказки полей мастера и сообщения `alert` / `confirm` / `prompt` — остаются по-русски;
- смена языка в другой вкладке подхватывается событием `storage`; у `/settings` собственный мини-словарь (`S_EN` / `t2`) на том же ключе `crmpanel:lang`.

## Главная (view-home)

Настраиваемая сетка виджетов (`WIDGETS`):

| Виджет | Что показывает |
|---|---|
| `summary` «Сводка по коммуникациям» | четыре KPI-плитки — **демо-числа** |
| `tasks` «Мои задачи» | to-do в `crmpanel:tasks` |
| `recent` «Недавно использованные инструменты» | последние 6 открытых разделов (`trackRecent`, `crmpanel:recent`) |
| `quicklinks` «Быстрые ссылки» | листья навигации (`navLeaves()`) с учётом приложения и `aclAllows` |
| `status` «Статусы систем» | **демо-данные для MVP** |

Раскладка — `crmpanel:layout` (по умолчанию `summary / tasks / recent / quicklinks`), режим настройки включает кнопка «Настроить главную»: виджеты можно перетаскивать, удалять крестиком и добавлять «чипами» из строки под сеткой.

## ACL-контракт оболочки и api.js

`renderNav()` рисует, `applyNavAcl()` (в `api.js`) фильтрует — контракт держится на data-атрибутах `.nav-item`:

| Атрибут | Кто ставит | Что делает applyNavAcl |
|---|---|---|
| `data-envs` | пункты с `envs:[...]` (сейчас таких нет) | удаляет пункт, если имя среды из `/api/env` не входит в список |
| `data-admin-only` | `adminOnly:true` («Цепочки») | удаляет пункт для не-админов |
| `data-group` + `data-children` | группы сайдбара | id группы — не раздел, по `me.sections` не фильтруется; группа скрывается, когда скрыты **все** её ACL-дети (в `data-children` — acl-id детей без `noAcl`) |
| `data-no-acl` | клиентские разделы без серверной секции («Планирование промо», дети «Загруженных инструментов») и группы, у которых есть такой ребёнок | пункт не фильтруется по `me.sections`; группа с no-acl ребёнком видима всегда |
| `data-acl-section` | «Просмотр настроек» (`viewer` → `admin`), отчёты (`rep-*` → `reports`), «Базовая работа кампаний» (→ `monitoring`) | пункт следует правам **другого** раздела |
| `data-nav-ref` | карточки обзорных страниц | скрываются синхронно с правами соответствующего пункта |

Кроме фильтрации `applyNavAcl` подписывает `#userEmail`, ставит на `<body>` атрибуты `data-role` и (для не-редакторов) `data-readonly="1"`, показывает шестерёнку `/settings` админам и, если активный пункт оказался скрыт, открывает первый видимый. Оболочка после каждой перерисовки сайдбара (смена приложения или языка, `syncAppSections`) переприменяет ACL — ради этого `window.applyNavAcl` и экспортирован.

Всё это только UX: сервер проверяет права сам, см. [[Безопасность и RBAC]].

## Настроечная админка /settings

`src/main/resources/static/settings/index.html` — самостоятельная страница вне SPA, с той же айдентикой (свой сайдбар, кнопка «← В панель управления», собственные `store`, `applyTheme` и мини-i18n `S_EN` / `t2`). Доступ закрыт на сервере правилом на `/settings/**` (см. [[Безопасность и RBAC]]); в SPA на неё ведёт шестерёнка в шапке. Меню строится из массива `PANES`, из него же собирается обзорная страница.

| Панель | Что настраивает |
|---|---|
| **Обзор** | карточки всех остальных панелей |
| **Приложения и разделы** | «приложение App Launcher → доступные разделы» (чекбоксы по 5 приложениям × разделам `home`/`comms`/`reports`/`dash`/`monitoring`/`uploads`; «Главная» всегда включена) и **«Очерёдность подразделов»** для `comms` / `reports` / `dash` |
| **Мониторинг** | блоки «Работа с партнёрами»: Поступление статусов · Зависшие статусы отправок · Записи отправок без идентификатора клиента · Наличие переменных Context API — все **заглушки** «Статистика в разработке» |
| **Загруженные инструменты** | таблица HTML-инструментов панели (то же хранилище `crmpanel:uploadedTools`): переименовать / удалить |
| **Управление доступом** | пользователи и роли — см. [[Управление доступом и вход]] |
| **Общие параметры** | тема оформления и язык интерфейса (`crmpanel:theme` / `crmpanel:lang`); те же значения, что у кнопки «Вид» в шапке |
| **Диагностика** | занятость `localStorage` ключами `crmpanel:*`, а также блоки «Подключения к БД», «Очередь синка шаблонов», «Прод-БД (синк шаблонов)» и «Синк из прода (ETL)» — см. [[Синхронизация с прод-БД]] |

«Приложения и разделы» — **единственный блок с серверным хранением**: источник истины `app.panel_settings` (ключ `appSections`, `GET/PUT /api/panel-settings/appSections`), сохранённое значение дополнительно зеркалится в `crmpanel:appSections`, чтобы оболочка применила его сразу; кнопка «Сбросить» пишет пустой объект = все разделы всем. Ошибки 403/404/сети выводятся строкой статуса, при недоступности сервера страница работает от умолчаний. «Очерёдность подразделов» и «Общие параметры» — клиентские, только `localStorage`.

Мелочь на будущее: в списке «Очерёдность подразделов» (`SUBSECTIONS`) для раздела «Отчёты» перечислены только `rep-planfact`, `rep-matrix`, `rep-leadgen` и `rep-demo` — новый отчёт `rep-smscheck` туда пока не добавлен и переставить его нельзя.
