# Оболочка панели (shell)

Оболочка SPA после большого обновления фронта устроена по образцу **Salesforce Lightning**: глобальная шапка с App Launcher-«вафлей», левый сайдбар разделов с всплывающим меню 2-го уровня, обзорные страницы групп, тема light/dark/system и i18n RU/EN. Прежнее горизонтальное верхнее меню **удалено**. Всё описанное живёт в инлайновых скриптах `src/main/resources/static/index.html` (блок «ОБОЛОЧКА», ~строки 3390–4300); RBAC-фильтрацию поверх выполняет `applyNavAcl()` из `api.js` (см. [[Обзор фронтенда]]).

## Глобальная шапка (gheader)

Слева направо: логотип **CRM Team** → кнопка-«вафля» `#waffleBtn` (App Launcher) → название текущего приложения `#appName` → бейдж среды `.env-pill` (добавляется после ответа `CRM.envReady`) → справа кнопка «Настроить главную» (`#homeActions`, видна только на Главной), **шестерёнка `#settingsLink`** (ссылка на настроечную админку `/settings`; скрыта по умолчанию, `applyNavAcl` показывает её только админам — `me.isAdmin`) и блок пользователя `#userEmail` + «Выйти».

## App Launcher: приложения

По клику на вафлю открывается панель `#launcher` со списком **пяти приложений** (константа `APPS`):

| Приложение | Подпись |
|---|---|
| Администрирование | Полный набор разделов панели |
| Аналитика | Дашборды, статистика и отклонения |
| Маркетинг | Коммуникации, шаблоны и кампании |
| Бизнес | Бизнес-инструменты и отчётность |
| Контактный центр | Управление настройками контактных центров |

Текущее приложение хранится в `localStorage` (`crmpanel:app`, по умолчанию «Администрирование»). Набор разделов, доступных каждому приложению, задаётся конфигом `crmpanel:appSections` (`{ "Приложение": ["home", ...] }`; `null`/пустой объект = все разделы): `allowedSections()`/`appAllows(sid)` фильтруют пункты 1-го уровня, `childVisible(k)` — детей с полем `appOnly` (сейчас так ограничена только «Тепловая карта» — приложение «Маркетинг», `updateAppSpecific()` управляет и её карточкой на обзорной странице). **Истина конфига — в БД** (`app.panel_settings`, ключ `appSections`): `syncAppSections()` в `api.js` при загрузке тянет `GET /api/panel-settings/appSections`, зеркалит в localStorage и перерисовывает сайдбар; редактируется конфиг в настроечной админке `/settings` (см. [[Управление доступом и вход]]). При смене приложения `setApp()` перерисовывает launcher и сайдбар, а если открытый раздел/подраздел в новом приложении недоступен — уводит на Главную или обзор раздела.

## Сайдбар и дерево NAV

Массив `NAV` (`index.html`, ~строка 3395) стал **двухуровневым**: элемент с `children` — группа, по наведению показывает flyout с подразделами, по клику открывает **обзорную страницу** (`overviewView`); дочерний элемент указывает `view` (id секции) и, для админки, `adminMode`. Комментарий в коде: «id разделов НЕ менять: на них завязан RBAC (me.sections)».

| 1-й уровень | 2-й уровень (children) | Особенности |
|---|---|---|
| `home` Главная | — | `view-home`, виджеты |
| `comms` Управление коммуникациями | `onelink` OneLink Builder · `admin` Мастер коммуникаций (`adminMode:"wizard"`) · `templates` Список шаблонов (`list`) · `viewer` Просмотр настроек (`view`, `aclSection:"admin"`) · `srcbuilder` Конструктор source (`noAcl`) · `heatmap` Тепловая карта (`noAcl`, `appOnly:["Маркетинг"]`) | обзор `view-comms-overview` |
| `dash` Дашборд | `dashboard` Общая статистика (`adminMode:"dashboard"`) · `deviations` Панель отклонений | обзор `view-dash-overview` |
| `monitoring` Мониторинг | `mon-campaigns` Базовая работа кампаний (`noAcl`) | обзор `view-mon-overview` |
| `uploads` Загруженные инструменты | динамические: «Загрузить инструмент» + по пункту на инструмент | `noAcl`, `view-uploads` |
| `journeys` Цепочки | — | `envs:["test"]` **и** `adminOnly:true` |
| `access` Управление доступом | — | `adminOnly:true` |

`renderNav()` строит пункты `.nav-item` и вешает data-атрибуты ACL-контракта (см. ниже); сайдбар можно свернуть (`#collapseBtn`, `crmpanel:sidebarCollapsed`). **Flyout 2-го уровня** (`#flyout`) появляется по наведению на группу (таймер 200 мс), список детей фильтруется `childVisible` (appOnly) и `aclAllows` — клиентским зеркалом правил `applyNavAcl` для динамически строящихся списков (flyout, «Быстрые ссылки» на главной).

### openSection(sid, cid)

Единая точка навигации: группа без `cid` открывает обзорную страницу; поддерживается **совместимость со старой плоской навигацией** — `openSection('admin')` (например, из `journeys.js`) сам находит родителя и превращается в `openSection('comms','admin')`. Дальше: проверки `appAllows` и `sectionAllowed` (env-гейтинг), переключение `.view`/`.nav-item`, хуки живого приложения (`setAdminMode`, `renderAccessSection`, `initJourneysSection`, лечение Chart.js в «Отклонениях»), `trackRecent`, `document.title`, запись `lastSection` (`{sid, cid}`; при старте мигрируется старый строковый формат). Восстановление последнего раздела — только после ответа `/api/env` (конец `index.html`).

## Обзорные страницы групп

`view-comms-overview` / `view-dash-overview` / `view-mon-overview` — сетки карточек `.ov-card` подразделов с описаниями и «Открыть →». Каждая карточка несёт `data-nav-ref="<id>"` — `applyNavAcl` скрывает её синхронно с правами соответствующего пункта NAV (карточка «Просмотр настроек» дополнительно несёт `data-acl-section="admin"`, клиентские — `data-no-acl`). Карточка тепловой карты (`#ovHeatmapCard`) скрыта всегда, кроме приложения «Маркетинг» (`updateAppSpecific`).

## Мониторинг (заглушки)

Раздел «Мониторинг» → подраздел «Базовая работа кампаний» (`view-mon-campaigns`): пять блоков-карточек контрольных точек жизненного цикла кампании (Работа отбора базы · Наличие поступления событий · Наличие отправок коммуникаций · Наличие доставок · Дублирование отправок). Клик по блоку открывает `monDetail(title)` — **заглушку** «Статистика в разработке» с кнопкой «← К блокам мониторинга» (`monBack`); реальных данных пока нет. Второй набор блоков мониторинга («Работа с партнёрами») живёт в настроечной админке `/settings`.

## Загруженные инструменты

Раздел `uploads`: пользователь загружает **свои HTML-страницы** внутрь панели. Файлы хранятся в `localStorage` (`crmpanel:uploadedTools`, объекты `{id, name, html, ts}`); лимит хранилища ~5 МБ — при переполнении `saveTools()` показывает alert. Загрузка — drag&drop или выбор файла (`uploadFormHtml`/`wireUploadForm`), название берётся из поля либо распознаётся из `<title>`/`<h1>` (`detectToolName`). Инструмент появляется карточкой в обзоре раздела и пунктом во flyout (`uploadChildren()`), открывается во встроенном окне **в исходном оформлении** (без адаптации под тему панели); на странице инструмента доступны «Переименовать»/«Удалить». Управлять инструментами можно и из `/settings` («Загруженные инструменты» — то же хранилище браузера).

## Тема light / dark / system

`applyTheme()`: настройка в `crmpanel:theme` (`dark` — по умолчанию, `light`, `system` — по `prefers-color-scheme`); светлая тема включается классом **`html.theme-light`** на корневом элементе. Переменные светлой темы перекрываются и для оболочки, и для корней всех `@scope`-секций (`#sec-admin`, `#sec-onelink`, `#sec-deviations`, `#sec-srcbuilder`, канва `#jrCanvas`, модалки цепочек и т.д.) — светлыми становятся **все разделы**, не только шапка. Тема реагирует на смену системной (`matchMedia("(prefers-color-scheme: light)")`) и на изменение в другой вкладке (событие `storage`). Выбирается в `/settings` → «Общие параметры».

## i18n RU / EN

Язык — `crmpanel:lang` (`ru` по умолчанию), применяется `applyLang()`:

- словарь `I18N_EN` (строка RU → строка EN) + `I18N_HTML` (токены для заголовков с градиентной разметкой, напр. `h1_comms`); функции `t(s)` / `tt(token)`;
- статичная разметка переводится `translateStatic()` по атрибутам `data-i18n` (текст), `data-i18n-html` (токен), `data-i18n-ph` (placeholder);
- динамика: `applyLang(true)` перерисовывает launcher/сайдбар/виджеты и зовёт `translateAdminChrome()` (перерисовка списка шаблонов, карточки просмотра, сброс кэша «Управления доступом» через `window.accessInvalidate`); `admin-users.js` переводится через свою обёртку `tr()` → глобальный `t()`;
- **осознанно не переведены**: подсказки полей `FIELD_HELP_TEXTS` и alert/confirm/prompt-сообщения — остаются по-русски;
- смена языка в другой вкладке подхватывается событием `storage`; настроечная админка `/settings` имеет собственный словарь (`S_EN`/`t2`) с тем же `crmpanel:lang`.

## Главная (view-home)

Настраиваемая сетка виджетов: `WIDGETS` = `summary` (KPI-плитки, демо), `tasks` (todo в localStorage), `recent` (последние открытые разделы, `trackRecent`), `quicklinks` (ссылки на разделы с учётом `aclAllows`), `status` (статусы систем, демо). Раскладка — `crmpanel:layout` (по умолчанию `summary/tasks/recent/quicklinks`), режим настройки — кнопка «Настроить главную».

## ACL-контракт оболочки и api.js

`renderNav()` рисует, `applyNavAcl()` (в `api.js`) фильтрует — контракт держится на data-атрибутах `.nav-item`:

| Атрибут | Кто ставит | Что делает applyNavAcl |
|---|---|---|
| `data-envs` | пункты с `envs:[...]` («Цепочки») | удаляет пункт, если имя среды из `/api/env` не входит в список |
| `data-admin-only` | `adminOnly:true` («Цепочки», «Управление доступом») | удаляет пункт для не-админов |
| `data-group` + `data-children` | группы сайдбара | id группы — не раздел, по `sections` не фильтруется; группа скрывается, когда скрыты **все** её ACL-дети (в `data-children` — acl-id детей без `noAcl`) |
| `data-no-acl` | клиентские разделы без серверной секции (srcbuilder, heatmap, monitoring, uploads) и группы с такими детьми | пункт не фильтруется по `me.sections`; группа с no-acl детьми видима всегда |
| `data-acl-section` | «Просмотр настроек» (`viewer`) | пункт следует правам **другого** раздела (viewer → `admin`) |
| `data-nav-ref` | карточки обзорных страниц | скрываются синхронно с правами соответствующего пункта |

После фильтрации `applyNavAcl` подписывает `#userEmail`, показывает шестерёнку `/settings` админам и, если активный пункт оказался скрыт, открывает первый видимый. Оболочка после каждой перерисовки сайдбара (смена приложения/языка, `syncAppSections`) переприменяет ACL — `window.applyNavAcl` экспортирован именно для этого. Всё это только UX: сервер проверяет права сам ([[Безопасность и RBAC]]).
