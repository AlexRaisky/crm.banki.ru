# Конструктор source и OneLink Builder

Два клиентских генератора из группы «Управление коммуникациями». Оба собирают имя кампании по одним и тем же правилам нейминга и оба ничего не сохраняют — результат человек копирует руками. Сервер задействован ровно в одном месте: справочник партнёров.

| Раздел | Секция | Файл | Что отдаёт |
|---|---|---|---|
| Конструктор source | `#sec-srcbuilder` | `js/srcbuilder.js` | значение `source` / `campaign_name` |
| OneLink Builder | `#sec-onelink` | `js/onelink.js` | готовую ретаргетинговую ссылку AppsFlyer |

Те же формулы живут в карточке шаблона (`sfdComputeCampaignName`) и в «Планировании промо». Каноническое описание правил — в [Мастер коммуникаций (формы)](Мастер%20коммуникаций%20(формы).md); здесь — только то, чем отличаются эти два экрана.

## Общее для обоих

Поля второй части формы меняются по типу кампании (`js/srcbuilder.js:23`, `js/onelink.js:74`): для `promo` показываются партнёр, уникальное имя и дата, для `trigger` — уникальное имя и день, а номер сегмента добавляется только для канала «КЦ». Скрытое поле в обязательные не попадает — подсветка недостающего смотрит на `offsetParent` (`js/srcbuilder.js:80`).

Результат закреплён карточкой сверху и имеет два состояния: «ЧЕРНОВИК — заполните обязательные поля» и «ГОТОВО — можно копировать». Пока черновик, кнопка копирования выключена.

**Копирование сделано с запасным путём** (`js/srcbuilder.js:98`, `js/onelink.js:227`). `navigator.clipboard` существует только в защищённом контексте — по HTTPS или на localhost. Панель отдаётся по `http://crm.banki.ru`, поэтому объекта там просто нет: обращение бросало `TypeError`, его глотал пустой `catch`, и кнопка молча не делала ничего. Теперь при отсутствии защищённого контекста текст кладётся через скрытое поле и `document.execCommand("copy")` — способ устарел, но работает; а об отказе кнопка сообщает вслух («Не удалось — скопируйте вручную»), потому что молчащая кнопка хуже честной ошибки.

## Конструктор source

Собирает **только значение `source`** — то, что в карточке шаблона лежит в поле «Campaign name», а в ссылке OneLink уходит в параметр `c`.

Каналы: `sms`, `mobile-push`, `email`, `callcenter`. Для КЦ первая часть имени — `contact`, и у promo к дате дописывается `day` (`js/srcbuilder.js:54`) — так же, как это делает карточка.

Партнёр — свободный ввод с подсказками из `dictionary.d_partner` (`CRM.dictPartners`) и кнопкой «+», которая заводит новое значение (`CRM.dictAddPartner`, `js/srcbuilder.js:156`). Если такое написание уже есть в загруженном списке, запрос не уходит: поле просто выравнивается по справочнику.

Значение рисуется по частям — каждый сегмент отдельным элементом, подчёркивания между ними (`js/srcbuilder.js:74`): в длинной строке из шести кусков глазом иначе не разобрать, где кончается продукт и начинается партнёр.

## OneLink Builder

Генератор ретаргетинговых ссылок AppsFlyer OneLink на папку `JmaP` (`ONE_LINK_BASE`, `js/onelink.js:3`). Имя кампании считается тем же кодом, что в конструкторе source, и показывается отдельной строкой предпросмотра.

В ссылку уходят: `af_xp` (`email` для почты, иначе `text`), `pid` — канал, `c` — имя кампании, `af_channel`, `aff_unique5`, флаги ретаргетинга `is_retargeting=true`, `af_reengagement_window=30d`, `af_force_deeplink=true`, затем `af_dp` и `deep_link_value`, при необходимости `af_ios_url` / `af_android_url` и всегда `af_web_dp` (`js/onelink.js:188`).

Тонкости, ради которых код выглядит именно так:

- **Плейсхолдеры зависят от канала**: для email это `{{aff_unique5}}` и `{{linkSourceCRM}}`, для остальных — `{AFFUNIQUE5}` и `{sourceCrm}` (`js/onelink.js:47`). Разные системы рассылки подставляют значения по-разному.
- **Фигурные скобки переживают кодирование**: `encodePreservingBraces` (`js/onelink.js:38`) возвращает `{` и `}` обратно после `encodeURIComponent`, иначе платформа не узнала бы свой плейсхолдер.
- **Deep link нормализуется** (`js/onelink.js:23`): срезаются схема `BankiRuInfo2://`, `https://www.banki.ru/`, ведущие слэши; заранее закодированное значение сначала раскодируется. Иначе адрес кодировался бы дважды.
- **`af_dp` и `deep_link_value` собираются из одного сырого пути** и кодируются одинаково, по одному разу (`js/onelink.js:197`) — расхождение между ними ломало открытие приложения.
- **Режим webview**: при включённом флаге поле diplink заменяется фиксированным префиксом и блокируется, а адрес страницы получает utm-разметку и кодируется отдельно, до вставки внутрь `webviewUrl` (`js/onelink.js:135`) — иначе его собственный query смешивался бы с параметрами диплинка.
- **utm-medium зависит от типа рассылки**: `adv` и `info` дают `email`, остальное — `crm` (`js/onelink.js:49`).
- Черновик показывается не только при незаполненных полях, но и при **невалидном URL** в `af_web_dp`, `af_ios_url`, `af_android_url` или webview (`js/onelink.js:181`); в примечании прямо перечислено, что заполнить и что проверить.

Подсказки у полей здесь — статические CSS-тултипы в разметке, а не общий попап; как их удерживают в пределах экрана, описано в [Оболочка панели (shell)](Оболочка%20панели%20(shell).md).
