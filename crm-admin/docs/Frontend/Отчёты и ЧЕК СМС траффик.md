# Отчёты и ЧЕК СМС траффик

Группа «Отчёты» в сайдбаре — пять пунктов и три разных механики:

| Пункт | Что это | Код |
|---|---|---|
| Plan-Fact · CRM Matrix · CRM Leadgen | встраивание книг Tableau, все три в одной секции `#view-report-embed` | `js/reports.js` |
| ЧЕК СМС траффик (`#view-report-smscheck`) | таблица «по дням» на странице + выгрузка `.xlsx` | `js/smscheck.js` |
| Пример визуализации отчёта (`#view-reports`) | демо-макет на плейсхолдерах, ни одного запроса к данным | `js/reports.js` |

Серверная сторона обоих рабочих отчётов — в [Отчёты](../Backend/Отчёты.md), контракты — в [REST API](../API/REST%20API.md).

## Отчёты Tableau

Встраивание сделано **веб-компонентом `<tableau-viz>`** из Tableau Embedding API v3, а не `iframe`: сам API подгружается ES-модулем с того же сервера Tableau, куда подключаемся (`js/reports.js:500`), и дедуплицируется по атрибуту `data-tableau-api` (`js/reports.js:509`) — три отчёта подряд не должны тянуть скрипт трижды.

Три книги объявлены в `RP_EMBED` (`js/reports.js:260`), а какую показать — решает пункт сайдбара: `openSection` зовёт `rpEmbedOpen(report)`. Секция физически одна.

**Адрес книги, сервер и токен в коде не зашиты.** Конфиг `{server, view, token}` на каждый отчёт лежит на сервере и читается через `GET /api/reports/connections` (`js/reports.js:283`), пишется `PUT`, стирается `DELETE` (`js/reports.js:302`, `js/reports.js:330`). Отдельный контроллер, а не общий `/api/panel-settings`, потому что в значении лежит токен — подробности в [Отчёты](../Backend/Отчёты.md).

Тонкости, которые видно только в поведении:

- `rpEmbedOpen` (`js/reports.js:377`) **всегда перечитывает конфиг с сервера**, даже если он уже в памяти: настройки общие на всех, и их мог поменять другой админ. Но если что-то уже показано, старая картинка не сбрасывается заглушкой — иначе при каждом переходе между отчётами экран моргал бы.
- Параллельные вызовы переиспользуют один промис `RP_EMBED_REQ` (`js/reports.js:269`).
- Право на правку берётся **из ответа сервера** (`res.canEdit`, `js/reports.js:290`), а не из клиентских флагов. Форма подключения не «серая», а физически скрыта для не-админа (`js/reports.js:339`); ему при пустом конфиге показывается «Отчёт пока недоступен — обратитесь к администратору» (`js/reports.js:479`).
- Пока фокус внутри формы `#rpSetup`, поля не перезаписываются пришедшим ответом (`js/reports.js:418`) — иначе набранный адрес затирался бы фоновым обновлением.
- У сохранённого токена в поле стоит плейсхолдер «токен сохранён — оставьте пустым, чтобы не менять» (`js/reports.js:427`): наружу токен не отдаётся, стереть его можно только кнопкой «Очистить».
- Решение «развернуть блок настроек» сбрасывается при переходе на другой отчёт (`js/reports.js:379`).

## ЧЕК СМС траффик

Раздел (`js/smscheck.js`) делает две вещи над одними и теми же данными: показывает лист «по дням» прямо на странице и отдаёт целую книгу Excel. Числа сходятся, потому что оба берутся с сервера из одного расчёта.

### Фильтры и кнопки

Панель: **Месяц** (`input[type=month]`, по умолчанию текущий), **Канал** (SMS / Push / Email), **Продукт** и две кнопки — «Обновить» и «⭳ Скачать Excel».

Список продуктов зависит от периода, поэтому он не зашит в разметку, а тянется под выбранный месяц и канал (`GET /api/reports/sms-check/products`, `js/smscheck.js:61`). Если в витрине колонки продукта нет — фильтровать нечем, и весь селект прячется целиком (`js/smscheck.js:77`): выбор, который ни на что не влияет, хуже отсутствия выбора. Когда сервер отдал известные значения сразу, а витрину опрашивает в фоне (`pending`), список один раз перечитывается через 6 секунд — один повтор, не цикл (`js/smscheck.js:84`).

**Отчёт считается только по кнопке «Обновить» и только с выбранным продуктом.** Оба ограничения намеренные:

- при открытии раздела расчёт не запускается вовсе (`js/smscheck.js:33`) — запрос к DWH тяжёлый, гонять его на каждый заход в раздел незачем;
- без продукта `scShowDaily` показывает приглашение и выходит (`js/smscheck.js:203`): запрос по всем продуктам сразу — самый дорогой, а смотрят всегда конкретный. Кнопка при этом остаётся нажимаемой, чтобы было видно, чего не хватает;
- смена месяца или канала не пересчитывает отчёт, а **стирает показанные числа** (`js/smscheck.js:49`): цифры за август под заголовком «сентябрь» хуже, чем их отсутствие.

Последний показанный отчёт держится в памяти вкладки (`SC_LAST`, `js/smscheck.js:15`): при возврате в раздел таблица появляется сразу, а свежие числа догружаются следом — месяц закрыт, данные за него уже не меняются. Пока идёт пересчёт, старая таблица не стирается, а над ней показывается строка «Обновляем…» (`js/smscheck.js:209`).

### Выгрузка не стирает таблицу

Ход выгрузки пишется в отдельную строку состояния `#scStatus`, а не в область отчёта (`js/smscheck.js:163`). Раньше он писался туда же, где таблица, и стирал ровно то, ради чего человек в раздел и пришёл. Сообщение об успехе само уходит через 8 секунд.

Файл называется `check-sms-<канал>-<месяц>.xlsx` (`js/smscheck.js:178`). Панель заполняет только сырые листы дней, а все листы-представления Excel досчитывает при открытии — об этом и говорит текст после скачивания.

### Таблица «по дням»

`GET /api/reports/sms-check/daily` возвращает готовые строки, клиент только верстает и форматирует числа по признаку `unit` (`percent` / `ratio` / `money` / `int`, `js/smscheck.js:256`). Пустая ячейка — «делить не на что»: не было ни отправок, ни выдач. Отрицательные значения подсвечиваются (`js/smscheck.js:255`) — в GM и динамике именно их ищут глазами.

Таблица широкая по определению (31 день плюс итог), поэтому листается внутри рамки, а не растягивает страницу; шапка и колонка названий приклеены (`css/section-reports.css:275`) — иначе на 20-м числе непонятно, какая это строка.

### Источник данных

Подключение к DWH выбирает админ прямо в разделе (блок `#scSetup`, скрыт по умолчанию и показывается по `canEdit` из `GET /api/reports/sms-check/config`). Список берётся из админского реестра подключений (`GET /api/admin/db-connections`, `js/smscheck.js:117`), встроенные подключения из него отфильтрованы — источником отчёта годятся только реальные внешние. Выбор общий для всех пользователей панели. Сами подключения заводятся в «Диагностике» — см. [Страница настроек (settings)](Страница%20настроек%20(settings).md).

Не-админу, если источник ещё не настроен, показывается «Источник данных ещё не настроен — обратитесь к администратору панели» (`js/smscheck.js:104`). Ошибки не прячутся: пустой список продуктов ничем не отличается от сломанного запроса, поэтому текст ошибки берётся из тела ответа, а не сводится к «HTTP 502» (`js/smscheck.js:63`).

## «Пример визуализации отчёта» — макет

Демонстрационный раздел без данных: три псевдоотчёта в константе `RP_DATA` (`js/reports.js:16`), виджеты (воронка, линия, группы, таблица) нарисованы собственным SVG без библиотек (`js/reports.js:90`). Окно Tableau сымитировано разметкой с явной плашкой «МАКЕТ», кнопки его футера декоративные, кроме «развернуть» — и та работает CSS-оверлеем, а не нативным полноэкранным режимом (`js/reports.js:222`). Селектор периода ни к чему не привязан. Кнопка «Обновить» просто показывает скелетон на 650 мс.

Раздел живёт как образец вёрстки под будущий коннектор, а не как отчёт.

## Стили

`css/section-reports.css` покрывает три секции сразу — `#view-reports`, `#view-report-embed` и `#view-report-smscheck` (`css/section-reports.css:2`). «ЧЕК СМС траффик» добавили в этот список не сразу, и последствия описаны в [Обзор фронтенда](Обзор%20фронтенда.md) — раздел пользуется той же разметкой `.rp-hero` / `.rp-toolbar` / `.rp-setup`, и без стилей панель фильтров разъезжалась.

Правило «секция — колонка-флекс» вешается только на `.active` (`css/section-reports.css:12`): безусловный `display:flex` перебил бы `.view{display:none}` из `shell.css` и показал бы все секции разом.
