# Мастер коммуникаций (формы)

Раздел «Мастер коммуникаций» (`<section id="sec-admin">` в `index.html`) — главный рабочий инструмент: здесь заводят и редактируют шаблоны коммуникаций четырёх каналов. Набор полей и лейблов взят из **v2** (Appsmith-экспорт), логика автогенерации имён — из v1; за инициализацию форм отвечает `src/main/resources/static/wizard.js`, за редактируемые дропдауны — `combobox.js`, за сохранение — инлайновые функции `index.html` + `CRM.saveFromV1` из `api.js`.

После объединения с оболочкой ([[Оболочка панели (shell)]]) секция `#sec-admin` работает в **четырёх режимах** (`setAdminMode`): `wizard` (мастер), `list` (Список шаблонов), `view` (Просмотр настроек), `dashboard`. Режимы переключает сайдбар — пункты `admin` / `templates` / `viewer` / `dashboard` группы «Управление коммуникациями» и «Дашборд»; прежняя полоса вкладок `#tabsBar` **скрыта всегда** (разметка и `openTab` сохранены для совместимости, `applyOnlyMode()` поддерживает `?only=list|dashboard`).

## Выбор канала: настроечный блок вместо вкладок

Канальные вкладки заменены **настроечным блоком канала** `#wizardChannelBar` (как у Salesforce): сегмент-переключатель `#wizardChannelSeg` с кнопками **SMS · Push · Email · КЦ** → `wizardSetChannel(ch)` активирует форму канала и, как раньше `openTab`, сбрасывает `window.CRM_CURRENT = null` — сохранение из формы канала всегда идёт как создание (INSERT), а не как обновление ранее открытого шаблона. В режимах `list`/`view`/`dashboard` блок канала скрывается.

## Формы каналов

Каждая форма — `<div id="{sms|push|email|cc}" class="form">` с тремя блоками: **1. Основные параметры**, **2. Флаги**, **3. Цепочка (и КЦ)**. Поля размечены CSS-классами, по которым `collectFormData(formEl, channel)` собирает данные в объект v1; дальше `CRM.v1ToDto` превращает его в `TemplateDto`.

### Общие поля всех каналов

| Поле (лейбл) | Класс | Значения / смысл |
|---|---|---|
| Communication Name | `.comname` (combobox) | Имя коммуникации; автодостраивается из базы + флагов (см. ниже) |
| Landing Page | `.aff_sub3` | Параметр aff_sub3 |
| Partner Name | `.partner` | Партнёр; пересчитывает campaign_name |
| Sending Day | `.day` (number) | День отправки; для trigger попадает в campaign_name как `NdayN` |
| Campaign Name | `.source` | Автособираемое имя кампании (см. формулу ниже), редактируемое |
| Communication Tunnel | `.communication_type` | `adv` / `service` |
| Business Communication Type | `.biz_type` | `adv` / `service` / `info` |
| Sender Type | `.trigger` | `promo` / `trigger` — влияет на формулу campaign_name |
| Product Type | `.product` (select) | 21 значение из v2, по умолчанию `credits` |
| Touch point | `.touch` (select) | 16 значений из v2, по умолчанию `promo` |
| Active | `.active_flag` (checkbox) | Шаблон активен |
| Флаги «Горизонтали» | `.cb-marketplace`, `.cb-dialog`, `.cb-loyalty`, `.cb-national_rating`, `.cb-news` | Влияют на communication_name |
| Флаги «Настроечные» | `.cb-night_send`, `.cb-mobile_app`, `.cb-cross` | `mobile_app` и `cross` влияют на communication_name |

### Специфика каналов

- **SMS** (`#sms`): `Message Text` (textarea), `Sender Name` — select `Banki.ru`/`Bamm.ru`; чекбокс `SMS CallCenter` (`.cb-sms-cc`) — при включении campaign_name собирается с префиксом `contact` вместо `sms`; блок цепочки.
- **Push** (`#push`): `Message Text`, `Title Text` (`.title`), `Deep Link` (`.deeplink`), `Webview link` (`.webview`); блок цепочки. Скрытый input канала содержит `mobile-push` (историческое имя канала в v1), но на бэкенд шаблон уходит как канал `push`.
- **Email** (`#email`): `Sender Email` (`.email_from`, автоподставляется — см. ниже), `Letteros Id` (`.letteros_id`); чекбокс `Email CallCenter` (`.cb-email-cc`); блок цепочки. Флаги `service_flag`/`info_flag` выводятся из `biz_type` (`collectFormData`: `service_flag = biz_type === 'service'`, `info_flag = biz_type === 'info'`).
- **КЦ** (`#cc`): `Source System` — select `KASKO`/`INVEST`/`INSMORTGAGE`/`CPA`/`MPK`/`OSAGO`/`RKO`; `Segment` (`.segment`, number) — бизнес-идентификатор шаблона КЦ (становится `code`); `Host Id` (`.host_id`); `Segment Descr` (`.segment_desc`, textarea); `Kvint Campaign Id` (`.kvint`). Блока цепочки нет.

### wizard.js: наполнение селектов и подсказок

`wizard.js` держит справочники из v2 и на `DOMContentLoaded` наполняет формы:

- `PRODUCT_OPTIONS` — 21 продукт (`rko`, `deposits`, `creditcards`, … `credits`);
- `TOUCH_OPTIONS` — 16 точек касания (`promo`, семейство `abandoned-*`, `sign`, `issue`, `renewal`, `mobile-app`);
- `COMNAME_SEED` — стартовые подсказки communication_name (как в v1);
- `loadLiveComNames()` — по каждому каналу тянет живые значения из БД (`CRM.dictCommNames(channel)`) и подмешивает их **перед** сид-подсказками; если эндпоинт недоступен, остаются сиды.

### combobox.js — редактируемый дропдаун

`window.Combobox` — самодостаточный компонент без зависимостей: свободный ввод + подсказки (`data-options` / `Combobox.setOptions`), фильтрация по подстроке, максимум 200 пунктов, навигация стрелками, выбор Enter/кликом с диспатчем настоящих `input`/`change`, закрытие по Escape и клику вне.

### Подсказки полей (FIELD_HELP_TEXTS)

У **каждого поля** мастера, фильтров списка, просмотра и дашборда есть значок **(i)** с тултипом: `initFieldHelp()` проходит по `.field label` и группам флагов, подбирая текст из карты `FIELD_HELP_TEXTS` (ключ — лейбл поля в нижнем регистре; ~50 записей: от `code` и `campaign name` до `kvint campaign id` и групп «горизонтали»/«настроечные»). Подсказки написаны по-русски и **осознанно не переводятся** при смене языка интерфейса (как и alert-сообщения).

## Автогенерация имён

### communication_name

Поле хранит «базу» в атрибуте `data-comname-base`; итоговое значение достраивается `updateComNameFromContext()`:

1. позиция продукта определяется дефисом базы: `-cross` → `credits-cross` (продукт спереди), `out-trigger-` → `out-trigger-<партнёр>`, `abandoned-` и прочие `...-` → база + продукт; база без дефисов остаётся как есть;
2. флаги (порядок как в v2 `generateCommunicationName`): `marketplace-` префиксом, затем суффиксы **`-cross`**, `-dialog`, `-loyalty`, `-nr`, `-news`, `-mobile-app`. Учёт `-cross` — недавний фикс: раньше чекбокс Cross не попадал в communication_name (а через него — и в campaign_name).

Обратная связь тоже есть: при ручном вводе `onComnameEdited()` синхронизирует чекбоксы из текста (`updateCheckboxesFromComname`, включая `-cross`) и пересчитывает campaign_name, **не** перестраивая сам comname. При открытии сохранённого шаблона база восстанавливается `inferComNameBase()`: `out-trigger-*` → `out-trigger-`, суффиксы `-cross`/`-marketplace`/`-nr`/`-loyalty` → соответствующая суффиксная база, иначе значение целиком.

### campaign_name (поле Campaign Name / `source`)

`computeCampaignName(form, overrideDay)`:

| Канал | Sender Type | Формула |
|---|---|---|
| sms / push / email | `promo` | `{tab}_promo_{product}_{partner}_{comname}_{ddmmyy}` |
| sms / push / email | `trigger` | `{tab}_trigger_{product}_{comname}_{day}day` |
| cc | `promo` | `contact_promo_{product}_{partner}_{comname}_{ddmmyy}day` |
| cc | `trigger` | `contact_trigger_{product}_{comname}_{segment}_{day}day` |

`{tab}` — `sms` / `mobile-push` / `email`, но при включённом чекбоксе CallCenter (`.cb-sms-cc`/`.cb-email-cc`) заменяется на `contact`. Дата — текущая в формате `ddmmyy`. Пересчёт вызывается `buildSource(el)` из `oninput`/`onchange` полей partner/day/trigger/product/touch/segment; сначала достраивается communication_name, затем от него campaign_name. Те же формулы доступны отдельным клиентским разделом **«Конструктор source»** (`sec-srcbuilder`, см. [[Обзор фронтенда]]) и «безформенными» зеркалами карточки просмотра (см. ниже).

### Sender Email (только email)

`updateEmailSenderName()`: `biz_type=service` → `no-reply@email.banki.ru`, `info` → `inform@email.banki.ru`, touch `renewal` → `renewal@email.banki.ru`, sender type `trigger` → `offers@email.banki.ru`, `promo` → `advice@email.banki.ru`.

## Цепочка (Is chain)

Для sms/push/email можно завести серию шаблонов «по дням» одним заходом:

1. чекбокс `Is chain` (`.cb-chain`) показывает блок `.chain-field` (`toggleChainField`, `wizard.js`);
2. в поле «Дни цепочки» вводятся числа через запятую/пробел (напр. `0, 3, 7`); Enter или кнопка «Сгенерировать строки» вызывает `buildChainRows`: дни парсятся, проверяются на числовость и уникальность, строится таблица «День → редактируемые поля шаблона» (`.chain-table`; шапка таблицы тёмная — `background: var(--card2)`, читаемая в обеих темах);
3. колонки таблицы зависят от канала (`CHAIN_COLUMNS`): sms — `Message Text`; push — `Title Text`, `Message Text`, `Deep Link`, `Webview link`; email — `Letteros Id`;
4. при сохранении `readChainRows(formEl, channel)` читает строки и валидирует обязательные поля (sms: message; push: title+message; email: letteros_id) — при ошибке alert и отмена;
5. `saveFromChannelForm` создаёт **по отдельному шаблону на каждый день** последовательно (reduce по Promise): базовые данные формы + overrides строки + `day` строки + `source`, пересчитанный `computeCampaignName(formEl, row.day)` под конкретный день. Цепочка — всегда создание (`CRM_CURRENT = null`).

## Сохранение (saveFromChannelForm)

Валидация перед отправкой: для `cc` обязателен `Segment`; для `email` без цепочки — `Letteros Id`; для всех — непустой `Communication Name`. Одиночный шаблон: `source` пересчитывается финально, затем `CRM.saveFromV1(data)` (create или update по `CRM_CURRENT`); после успеха — alert с communication_name и выданным бэкендом `Code`, перезагрузка списка (`afterChannelSave` → `loadMockData` → `applyFilters`). Код шаблона для sms/push выдаёт бэкенд; для cc `code = segment`, для email идентификатор — letteros_id.

**A/B-тест**: чекбокс `.cb-ab-test` + «Количество шаблонов» (2–26). При сохранении создаётся по шаблону на каждый вариант; к communication_name добавляется суффикс через дефис: `-a`, `-b`, `-c`… (уже стоящий одиночный суффикс `-x` предварительно срезается).

## «Список шаблонов» — Salesforce list view

Режим `list` (`#list`) переделан под **SF list view**. Данные — `ALL_TEMPLATES` из `GET /api/templates` (`loadMockData()`; при ошибке сети — `applyFallbackData()` с зашитым демо-набором `FALLBACK_LIST_TEMPLATES`). Возможности:

- шапка объекта (`sf-head`): «Шаблоны коммуникаций · Все шаблоны», строка **поиска по списку** `#listSearch` (подстрока по code / названию / продукту / партнёру / touch / trigger) и «Сбросить фильтры»;
- фильтры-селекты: канал, продукт, touch point, trigger type, статус (активные/неактивные);
- **сортировка кликом по заголовку** (`listSortBy`, состояние `LIST_SORT`, индикатор ▲/▼);
- **счётчик** `#listStats` в стиле SF: «N элементов · Отсортировано по „…" · всего N (активных: A, неактивных: B)»;
- таблица `sf-table`: колонка чекбоксов (с «выбрать все» в шапке), Канал (бейдж), Code/ID и Название — **ссылки** `sf-link`, Продукт, Touch point, Trigger, Партнёр, Статус (● активный / ○ неактивный), кнопка меню строки ▾;
- клик по ссылке/кнопке → `viewFromList(id)`: ставит `window.CRM_CURRENT = {channel, code}` (дальнейшее сохранение пойдёт как UPDATE), тянет полный шаблон `CRM.getTemplate` → `CRM.dtoToV1` и открывает его в «Просмотре настроек» (`showTemplateInViewer` → `openSection('comms','viewer')`); при ошибке сети показывает частичные данные из строки списка.

## «Просмотр настроек» — карточка Salesforce Details

Теперь это **самостоятельный пункт NAV** `viewer` (режим `view` той же секции; ACL следует правам раздела `admin` через `data-acl-section`). Выбор шаблона: select `#templateSelect` (перестраивается из данных бэкенда `refreshViewTemplateSelect`, группировка по каналам, пометка «(неактивный)») или поиск по коду `searchTemplate()` — точное совпадение `code`; код уникален внутри канала, но может совпадать между каналами — показывается первый, остальные упоминаются подсказкой.

Старый рендер (клон формы канала + кнопка «Редактировать»: функции `renderTemplate`/`enableEditing`/`saveTemplate`) **удалён**. Вместо него — карточка **SF Details** (`renderTemplateDetails` → состояние `SFD_STATE {id, orig, work, editing, pushOS}` → `sfdRender`):

- **шапка**: бейдж канала, `код — communication_name`, статус АКТИВНЫЙ/НЕАКТИВНЫЙ; сверху кнопка «← К списку шаблонов»;
- **секции** (сворачиваются кликом по заголовку): «Основное», «Источник и сегментация», «Контент и ссылки» (кроме КЦ), «Служебные параметры и флаги» — набор строк зависит от канала (`sfdFieldDefs`);
- **построчное редактирование «карандашами»**: при наведении на строку появляется ✎ (`sfd-pen`), клик превращает значение в input/textarea/select/чекбокс; readonly-поля (канал, code, `Source_type`, сегмент КЦ) карандаша не имеют. Как только есть правки, снизу прилипает футер **«Сохранить / Отменить»**;
- **пересчёт имён**: правка любого поля из `SFD_NAME_KEYS` (trigger/product/partner/comname/day/segment и все флаги) вызывает `sfdRecalcNames()` → `sfdComputeComname` / `sfdComputeCampaignName` — «безформенные» зеркала `updateComNameFromContext` / `computeCampaignName`, работающие от объекта данных, а не от DOM-формы (DOM-версии сохранены — их использует мастер). `-cross` учитывается в обоих именах; флаг `cross` восстанавливается из communication_name (в БД отдельного поля нет), контекст «выгрузка в КЦ» — из префикса `contact_` сохранённого campaign_name; для email `service_flag`/`info_flag` следуют за `biz_type`;
- **предпросмотр коммуникации** в правой колонке (`sfdRenderPreview`): SMS — «пузырь» на макете телефона с именем отправителя; **Push — макеты iOS 17 / Android 14** с переключателем ОС (`sfdSetPushOS`), заголовком, текстом и deep link; Email — тема + вкладыш Letteros (если в `msgText` есть HTML — рендер в `iframe sandbox` через `srcdoc`, иначе заглушка «Вёрстка шаблона будет подтягиваться из Letteros»); у КЦ предпросмотра нет;
- **сохранение** (`sfdSave`): `sfdRecalcNames` → `CRM.v1ToDto(work)` → `CRM.updateTemplate(channel, code, dto)` (PUT); после успеха — alert, свежие данные перечитываются с бэкенда (`CRM.getTemplate` → `dtoToV1` → `renderTemplateDetails`), обновляются `ALL_TEMPLATES` (`loadMockData` → `applyFilters`) и select; «Отменить» возвращает исходные данные (`st.orig`).

## «Дашборд»

Режим `dashboard` (раздел NAV `dash → dashboard`): режимы «Общая статистика» и «По конкретному шаблону» (`switchDashboardMode`, `loadTemplateStats`). Данные пока демонстрационные (`FALLBACK_DASHBOARD`) — реальный источник статистики планируется следующими итерациями.
