# Мастер коммуникаций (формы)

Секция `#sec-admin` в `index.html` — главный рабочий инструмент панели: здесь заводят, ищут и правят шаблоны коммуникаций. Одна секция работает в **четырёх режимах** (`setAdminMode(mode)` из `js/shell.js`), которые выбираются пунктами сайдбара:

| Пункт NAV | Режим | Контейнер | О чём |
|---|---|---|---|
| `comms → admin` Мастер коммуникаций | `wizard` | `#wizard` / `#wizardOutput` | заведение нового шаблона |
| `comms → templates` Список шаблонов | `list` | `#list` | витрина всех шаблонов |
| `comms → viewer` Просмотр настроек | `view` | `#view` / `#settingsOutput` | карточка сохранённого шаблона |
| `dash → dashboard` Общая статистика | `dashboard` | `#dashboard` | сводные показатели (демо) |

Полоса вкладок `#tabsBar` скрыта **всегда** — режимы выбирает сайдбар, канал в мастере — настроечный блок `#wizardChannelBar`. `applyOnlyMode()` по-прежнему поддерживает URL-параметр `?only=list|dashboard`.

Файлы:

| Файл | За что отвечает |
|---|---|
| `js/template-details.js` | **Ядро раздела**: карточка шаблона (SFD) — и в мастере, и в просмотре; предпросмотр сообщения; создание и сохранение; пикер «Просмотра настроек» |
| `js/template-list.js` | «Список шаблонов»: загрузка страницами, фильтры, сортировка, настройка колонок, инлайн-правка |
| `js/dashboard.js` | Режим «Общая статистика» |
| `js/wizard-forms.js` | Библиотека функций старых форм: `formatDateDDMMYY`, подсказки полей, поиск и загрузка шаблона в просмотре |
| `wizard.js`, `combobox.js` | Справочники и редактируемые дропдауны **старых форм** |

## Важно: мастер — это карточка, а не форма

Развёрнутые формы каналов (`#sms`, `#push`, `#email`, `#cc`, `#fa`, `#vk`) **остались в разметке, но недостижимы**: `setAdminMode` всегда прячет `#tabsBar`, а `wizardSetChannel(ch)` снимает `.active` со всех `.form` и активирует `#wizard` — карточку в оформлении «Просмотра настроек».

Практические следствия, которые экономят время при чтении кода:

- `openTab()`, `collectFormData()`, `saveFromChannelForm()` вызываются только из скрытой разметки. Через интерфейс до них не добраться.
- `wizard.js` (`PRODUCT_OPTIONS`, `TOUCH_OPTIONS`, `COMNAME_SEED`, `loadTouchPoints`, `loadLiveComNames`, `CHAIN_COLUMNS`, `buildChainRows`, `readChainRows`) и `combobox.js` обслуживают **только** эти скрытые формы: все шесть `.combo-input` на странице — поля Communication Name внутри них. Карточка справочники тянет сама, а дропдаун делает нативным `input + datalist`.
- Из `js/wizard-forms.js` в живом пути работают только `formatDateDDMMYY()`, `showFieldHelp` / `hideFieldHelp`, `FIELD_HELP_TEXTS` / `initFieldHelp()` и функции пикера просмотра (`searchTemplate`, `loadTemplate`).
- Формулы имён продублированы: DOM-версии (`computeCampaignName`, `updateComNameFromContext`) — в `wizard-forms.js` для старых форм, «безформенные» (`sfdComputeCampaignName`, `sfdComputeComname`) — в `template-details.js` для карточки. Живая — вторая пара.

## Выбор канала

Настроечный блок `#wizardChannelSeg` — шесть кнопок: **SMS · Mobile-push · E-mail · КЦ · FA · VK** → `wizardSetChannel(ch)`. Как раньше `openTab`, он сбрасывает `window.CRM_CURRENT = null` — сохранение из мастера всегда идёт как создание (INSERT). В режимах `list` / `view` / `dashboard` блок канала скрыт.

Отдельной кнопки **Live Activity** нет: это разновидность пуша. В карточке канала Mobile-push при создании появляется тумблер **«Это Live Activity»** (`is_la`), который переключает сам канал (`push` ↔ `la`) и перерисовывает карточку с LA-полями. Тумблер есть только в режиме создания: у сохранённого шаблона смена канала — это переезд между таблицами.

Полный набор каналов, который знает раздел (`CH_LABELS`): `sms`, `push` / `mobile-push`, `email`, `cc`, `fa`, `vk`, `la`. Пикер «Просмотра настроек» показывает все семь, «Список шаблонов» фильтрует по всем семи.

## Карточка шаблона (SFD)

Одна и та же карточка обслуживает два режима, различаемых полем `SFD_STATE.mode`:

| | создание (`create`) | просмотр (`view`) |
|---|---|---|
| открывается | `wizardCardOpen(channel)` | `renderTemplateDetails(data, id)` |
| контейнер | `#wizardOutput` | `#settingsOutput` |
| поля | все не-readonly сразу открыты на ввод | текст, правка по карандашу |
| шапка | «Новый шаблон [· код] — communication_name» | «код — communication_name» + статус + кнопка «← К списку шаблонов» |
| секция «Цепочка» | есть (для sms/push/email) | нет |
| футер | «Создать шаблон» + «Очистить» | «Сохранить» + «Отменить» (появляется, как только есть правки) |

Состояние — `SFD_STATE = { id, orig, work, editing, mode, chain }`: `orig` — исходные данные, `work` — рабочая копия, `editing` — какие поля сейчас в режиме ввода. Заготовка нового шаблона — `sfdBlank(channel)`: `active: true`, `comname: "NoComName"`, `trigger: "promo"`, `day: "0"`, для SMS `sender_name: "Banki.ru"`.

Флаг `cross` в БД отдельного поля не имеет и при открытии шаблона восстанавливается из `communication_name` (по наличию `-cross`).

### Секции и поля (sfdFieldDefs)

Набор строк зависит от канала; секции сворачиваются кликом по заголовку.

**Основное** — «Это Live Activity» (только создание push/la), «Канал» (только просмотр, readonly), «Code» / для КЦ «Сегмент (code)» (в создании показывается только у КЦ; в просмотре readonly), «Статус» (`active`), **Communication name** (комбо с подсказками из справочника).

**Источник и сегментация** — «Campaign name» (`source`, **readonly**, собирается сам), «Trigger type» (`promo` / `trigger`), «Product type» (справочник), «Partner name» (комбо из справочника + кнопка «+», см. ниже), «Touch point» (справочник), «Sending day» (только цифры). Для VK добавляется «AB Group». Для КЦ — «Сегмент» (readonly), «Описание сегмента», «Source system», «Host Id», «Kvint campaign Id».

**Интеграция FA** (только канал FA) — `fa_id`, `channel_id`, «Need push», `c2d_transport`, `c2d_account`, `ch2d_operator_id`.

**Контент и ссылки** — набор по каналу:

- email — «Email from» (**readonly**, выводится из типа коммуникации) и «Letteros ID»; поля темы в карточке нет — тему проставляет отправка;
- sms — «Message text» и «Sender name» (`Banki.ru` / `Bamm.ru`);
- push — «Title», «Message text», «Deep link», «Webview link»;
- fa — «Link title», «Deep link», «Webview link», «Web url», «Action buttons (JSON)»;
- vk — «VK template name», «TTL», «Buttons (JSON)»;
- la — «Title», «Deep link», «Webview link», «Action buttons (JSON)»;
- **cc** — контентных полей нет, секция не выводится.

**Live Activity — параметры активности** (только `la`) — `activity_name`, `la_event`, `la_visualization`, `la_status`, `current_step`, «LA visualization attributes (JSON)».

**Служебные параметры и флаги** — «Communication tunnel» (`adv` / `service`), «Business communication type» (`adv` / `info` / `service`), «Landing page» (`aff_sub3`) и чекбоксы `marketplace`, `cross`, `dialog`, `loyalty`, `national_rating`, `news`, `mobile_app`, плюс `night_send` (кроме FA и VK).

### Подсказки: назначение поля и колонка в БД

У каждой строки карточки есть значок **(i)**. Текст собирается из двух карт `template-details.js`: `SFD_HELP` — назначение поля, `SFD_DB` + `SFD_TABLES` — **в какую колонку какой таблицы поле ложится** (`sfdDbField`). Например, `code` у email — это `notice.email_template.trigger_code`, у КЦ — `callcenter.d_segment_properties.segment`; у `channel` и `cross` подсказка честно говорит «отдельного поля нет». Таблицы каналов — см. [[Справочники шаблонов]].

Тултип рисуется в фиксированный контейнер `#fieldHelpPopup` (а не CSS-подсказкой у строки): та обрезалась краями карточки и секций.

Отдельно живёт старая система подсказок `FIELD_HELP_TEXTS` / `initFieldHelp()` из `wizard-forms.js` — она ищет `.field label` внутри `#sec-admin` и сегодня достаёт только фильтры списка, пикер просмотра, дашборд и скрытые формы. **Карточка ей не пользуется.** Обе системы пишут по-русски и при смене языка не переводятся.

### Правка карандашами и сохранение

В режиме просмотра при наведении на строку появляется ✎ (`sfd-pen`, только при праве `edit`), клик превращает значение в `input` / `textarea` / `select` / чекбокс. Числовые поля сделаны текстовыми с `inputmode=numeric` — не `type=number`. Readonly-строки карандаша не имеют.

Как только есть правки, снизу прилипает футер:

- **Сохранить** → `sfdSave()`: пересчёт имён → `CRM.v1ToDto(work)` → `window.CRM_CURRENT = {channel, code}` → `CRM.updateTemplate(channel, code, dto)`; после успеха данные перечитываются с бэкенда и карточка рисуется заново, обновляется список и `#templateSelect`;
- **Отменить** → возврат к `SFD_STATE.orig`.

### Создание

Блок «недостающих полей» (`sfdCreateMissing`) держит кнопку «Создать шаблон» заблокированной, пока не заполнены: код (**только у КЦ**), Product type, Touch point, communication_name (не `NoComName`) и контент канала — Letteros ID для email, Message text для остальных, кроме КЦ. При включённой цепочке требования по коду и контенту снимаются: они задаются построчно.

`sfdCreate()` → проверка права `add` → `sfdRecalcNames()` → для email `letteros_id` при необходимости берётся из кода → `window.CRM_CURRENT = null` → `CRM.saveFromV1(d)` (создание) → alert с communication_name и выданным бэкендом кодом → перезагрузка списка и чистая карточка. Кнопка «Очистить» пересоздаёт карточку с нуля.

### Предпросмотр сообщения

Правая колонка карточки (`sfdRenderPreview`), перерисовывается при каждом изменении:

- **SMS** — «пузырь» на макете телефона с именем отправителя;
- **Push** — карточка уведомления (иконка, «Banki.ru», заголовок, текст, при наличии — deep link) плюс **проверка на переполнение**: `sfdPushFit` сравнивает реальную высоту с видимой и пишет «Текст помещается…» либо «Не помещается: заголовок / текст — часть будет скрыта под „ещё“. Заголовок — 1 строка, текст — до 4 строк»;
- **FA / VK** — бабл мессенджера с кнопками, разобранными из JSON (`action_buttons` / `buttons`); для FA при `need_push` — примечание, что сообщение продублируется пушем;
- **Email** — `iframe` с версткой из Letteros (`https://app.letteros.com/webv/<letteros_id|code>`, `sandbox`, `referrerpolicy="no-referrer"`) и ссылкой «Открыть в Letteros ↗»; загрузка откладывается на 500 мс, чтобы не бить в Letteros на каждый введённый символ. Если адреса нет, но в `msgText` лежит HTML — он рисуется через `srcdoc` в изолированном `iframe`; иначе заглушка «Укажите Letteros ID…»;
- **КЦ и Live Activity** — предпросмотра нет.

Макетов iOS/Android у пуша **нет**: поле `SFD_STATE.pushOS` в коде объявлено, но нигде не читается.

## Цепочка (Is chain)

Секция появляется в карточке **только при создании** и только для каналов `sms`, `push`, `email` (`SFD_CHAIN_COLS`).

1. Чекбокс «Is chain — шаблон на каждый день цепочки» открывает поле дней и таблицу.
2. Дни вводятся числами через запятую (`0,3,7`); ввод санитайзится на лету — пробелы и `;` превращаются в запятую, чтобы «0 3 7» не слиплось в «037». Enter или кнопка «Сгенерировать строки» строит таблицу; дни проверяются на числовость и уникальность, уже заполненные значения при перегенерации сохраняются.
3. Колонки таблицы зависят от канала: sms — Message Text; push — Title Text, Message Text, Deep Link, Webview link; email — Letteros Id. Эти же поля временно исчезают из секции «Контент и ссылки» — они задаются построчно.
4. Обязательные по строкам (`SFD_CHAIN_REQ`): sms — message; push — title + message; email — letteros_id. Незаполненное поле — alert с номером дня.
5. Создание идёт **строго последовательно, по шаблону на день**: общая часть карточки очищается от по-дневных полей (иначе текст уезжал бы туда, где его не вводили), к ней подмешиваются значения строки и её `day`, `source` пересчитывается под конкретный день. Для email код шаблона берётся из Letteros Id. Цепочка — всегда создание.

## Автогенерация имён

### communication_name

`sfdComputeComname(d)`: у текущего значения срезаются все известные флаги (`sfdStripComnameFlags` — префикс `marketplace-` и суффиксы `-cross`, `-dialog`, `-loyalty`, `-nr`, `-news`, `-mobile-app`), база `out-trigger-` достраивается партнёром, затем флаги навешиваются заново в фиксированном порядке:

```
[marketplace-] база [-cross][-dialog][-loyalty][-nr][-news][-mobile-app]
```

### campaign_name (поле Campaign name / source)

`sfdComputeCampaignName(d)` — работает от объекта данных, не от DOM. Если `trigger` не `promo` и не `trigger`, имя не собирается вовсе.

| Канал | Sender type | Формула |
|---|---|---|
| sms / push / email / fa / vk | `promo` | `{ch}_promo_{product}_{partner}_{comname}_{ддммгг}` |
| sms / push / email / fa / vk | `trigger` | `{ch}_trigger_{product}_{comname}_{day}day` |
| cc | `promo` | `contact_promo_{product}_{partner}_{comname}_{ддммгг}day` |
| cc | `trigger` | `contact_trigger_{product}_{comname}_{segment}_{day}day` |

`{ch}` — не сам код канала, а его «имя в source»: `sms` → `sms`, `push` → **`mobile-push`**, `email` → `email`, `fa` → **`fin-assistent`**, `vk` → `vk`. Канала `la` в этой карте нет — в имя попадает `la` как есть.

Контекст «выгрузка в КЦ» отдельным полем не хранится: если сохранённый `source` начинался с `contact_`, префикс сохраняется и дальше.

### Sender email (только email)

`sfdComputeEmailFrom(d)` — порядок проверок значимый:

| Условие | Адрес |
|---|---|
| touch = `renewal` | `renewal@email.banki.ru` |
| biz_type = `service` | `no-reply@email.banki.ru` |
| biz_type = `info` | `inform@email.banki.ru` |
| trigger = `trigger` и biz_type = `adv` | `offers@email.banki.ru` |
| trigger = `promo` и biz_type = `adv` | `advice@email.banki.ru` |
| иначе | `newsletter@email.banki.ru` |

Результат показывается как `Банки.ру<адрес>`.

### Когда пересчитывается

`sfdRecalcNames()` вызывается при открытии карточки, при создании, при сохранении и при правке любого поля из `SFD_NAME_KEYS` (`trigger`, `product`, `partner`, `comname`, `day`, `segment`, `touch` и все флаги) либо `biz_type`. `touch` попал в список не ради имён, а ради адреса отправителя — `renewal` там первое условие. Пустой результат `campaign_name` **не затирает** сохранённое значение. Для email заодно выводятся `service_flag` / `info_flag` из `biz_type`.

## Справочники карточки

`sfdEnsureDicts(channel)` тянет четыре справочника по одному разу за загрузку страницы:

| Что | Метод |
|---|---|
| Touch point | `CRM.dictTouchPoints()` → `GET /api/dictionaries/touch-points` |
| Product type | `CRM.dictProductTypes()` → `GET /api/dictionaries/product-types` |
| Communication name | `CRM.dictCommNames(channel)` → `GET /api/dictionaries/comm-names?channel=` |
| Partner name | `CRM.dictPartners()` → `GET /api/dictionaries/partners` |

`sfdDictOpts(list, current, withEmpty)` при необходимости подмешивает **текущее значение**, если его нет в списке: иначе открытие старого шаблона со снятым из справочника значением молча подменяло бы его первым пунктом. Product и Touch — строгие селекты; communication_name и partner_name — комбо (`input` + `datalist`): новые значения заводятся регулярно, строгий список их бы отсёк. Контракты — [[REST API]].

### Пополнение справочника из карточки

У поля **Partner name** рядом с вводом стоит кнопка **«+»** (`sfd-dict-add`, видна при праве `add`): она заносит введённое значение в `dictionary.d_partner` (`POST /api/dictionaries/partners`) и подставляет обратно то, что вернул сервер — он мог вернуть уже существующее написание. Если такое значение уже есть в загруженном списке (регистр не важен), запрос не уходит вовсе, поле просто выравнивается по справочнику. После успеха значение добавляется в `SFD_DICT.partner`, и карточка перерисовывается — `campaign_name` пересчитывается сразу (`partner` входит в `SFD_NAME_KEYS`).

Какие поля так умеют, задаёт карта `SFD_DICT_ADD` — пока в ней только партнёр: остальные списки правятся осознанно, а партнёр появляется в работе раньше, чем кто-то успевает добавить его в справочник.

## «Список шаблонов» (Salesforce list view)

### Загрузка

Данные грузятся **страницами по 50 записей с бесконечной прокруткой**: `fetchListPage(reset)` собирает фильтры, сортировку, `limit` и `offset` и зовёт `CRM.listTemplates(params)` (`GET /api/templates`). Прокрутка ближайшего скроллящегося контейнера подтягивает следующую страницу, когда до конца остаётся меньше 300 px; сентинел `#listLoadMore` показывает «Загрузка…» или «— всё загружено —». Устаревшие ответы отбрасываются по счётчику запросов.

Отдельно считаются итоги: `CRM.countTemplates()` (`GET /api/templates/count`) — всего и активных, `CRM.facetsTemplates()` (`GET /api/templates/facets`) — реальные значения продуктов, точек касания, типов и партнёров для наполнения фильтров.

Функция называется `loadMockData()`, но **никаких mock-файлов не читает** — имя историческое. Аварийный набор `FALLBACK_LIST_TEMPLATES` (11 записей) существует, но практически недостижим: ошибку загрузки страницы список глотает сам.

### Фильтры, поиск, сортировка

- Пять **мультиселектов** — канал, продукт, touch point, trigger type, партнёр: внутри фильтра значения складываются по ИЛИ (несколько одноимённых query-параметров), между фильтрами — И. Подпись кнопки: «Все …» / единственное значение / «N выбрано».
- Статус — обычный селект (активные / неактивные).
- **Скрытый в настройках фильтр не применяется** — иначе выборка молча сужалась бы значением, которого не видно на экране.
- Строка `#listSearch` уходит на сервер параметром `q` — ищет по всей базе, а не по загруженной странице.
- Сортировка кликом по заголовку (`listSortBy`): повторный клик разворачивает направление, сортирует **сервер по всей выборке**, в заголовке ▲/▼.
- Счётчик `#listStats`: «N элементов (показано N из TOTAL — листайте, чтобы загрузить ещё) · Отсортировано по „…" · всего TOTAL (активных: A, неактивных: B)».

### Настройка отображения (шестерёнка)

Панель `#listPanel` содержит два блока: **«Отображаемые поля»** (колонки Канал, Code/ID, Название, Продукт, Touch point, Trigger, Партнёр, Статус) и **«Показывать фильтры»**. Настройки лежат в `localStorage` (`crmpanel:listCols`, `crmpanel:listFilters`), кнопка «По умолчанию» их сбрасывает. Последнюю колонку снять нельзя. Смена колонок — только перерисовка, смена набора фильтров — перезапрос.

### Правка прямо в таблице

У ячейки при праве `edit` есть карандаш; клик открывает редактор, рядом появляются ✓ («Применить») и ✕ («Отменить»), работают Enter и Escape. Сохранение (`listCellSave`) идёт «оптимистично»: значение сразу видно в таблице, затем читается полный шаблон (`CRM.getTemplate` → `CRM.dtoToV1`), в нём меняется одно поле (для email правка кода тянет за собой `letteros_id`) и уходит `CRM.saveFromV1` как UPDATE. Если сервер отказал — значение откатывается и показывается alert.

Клик по ссылке Code/ID или Названия → `viewFromList(id)`: ставит `window.CRM_CURRENT` (дальше сохранение пойдёт как UPDATE), тянет полный шаблон с бэкенда и открывает его в «Просмотре настроек» (`openSection('comms','viewer')`). При ошибке сети показываются частичные данные из строки списка.

Чего в списке **нет**: массовых действий (чекбоксы строк нарисованы, но ни один обработчик их не читает) и экспорта.

## «Просмотр настроек»

Самостоятельный пункт NAV `viewer`; ACL следует правам раздела `admin` (`aclSection`), см. [[Оболочка панели (shell)]].

Сверху — **пикер в два шага**: «1. Канал» (семь кнопок, включая Live Activity) → «2. Шаблон». Во втором блоке три поля поиска — по `source_type`, по Letteros ID (появляется только для email) и по Code — и выпадающий список.

Список строится `refreshViewTemplateSelect()`: запрос уходит **на сервер** с каналом и поисковой строкой, забирается не больше 500 позиций, и если упёрлись в потолок — в первой строке списка так и написано («первые 500 — уточните поиск»). Подпись пункта — `код — source_type` (если `source_type` пуст, берётся communication_name) плюс пометка «(неактивный)».

Поиск по коду (`searchTemplate`, Enter в поле Code) ищет на бэкенде по всей базе и оставляет **точное** совпадение кода или Letteros ID. Код уникален внутри канала, но может совпадать между каналами: показывается первый, про остальные пишется подсказка с предложением искать через «Список шаблонов».

Дальше открывается та же карточка SFD, что и в мастере, но в режиме просмотра.

## «Общая статистика» (дашборд)

Режим `dashboard`. **Данные полностью демонстрационные**: `js/dashboard.js` не делает ни одного запроса к API, а глобальная `DASHBOARD_DATA` безусловно получает зашитый набор `FALLBACK_DASHBOARD` (комментарий в коде: «Дашборд пока вне скоупа — оставляем демо-данные»). Кнопка «Обновить данные» не ходит на сервер, а слегка рандомизирует числа и переставляет время последнего обновления.

Что нарисовано: четыре KPI (отправки сегодня, среднее за месяц, успешные, ошибки), статистика по каналам, «Коммуникаций на одного человека», «Индикатор перегрева базы» (порог `MAX_COMM_PER_USER = 3`: Норма / Внимание / Перегрев), размер активной аудитории, пересечение каналов, доля недоступных ни в одном канале, топ-5 активных сегментов, топ-5 с худшей доставкой, среднее число коммуникаций на пользователя за 7 и 30 дней, доля получивших больше N сообщений, топ-10 перегруженных сегментов, отписки после X контактов, столбики отправок и дублей за 7 дней (нарисованы вручную, без Chart.js) и топ-5 шаблонов. Режим «По конкретному шаблону» работает от второго демо-набора `TEMPLATE_STATS`, список шаблонов в селекте зашит прямо в разметку.

## Права

Раздел смотрит на `CRM.can(cap, …sections)` — клиентское зеркало серверного контроля прав ([[Безопасность и RBAC]]):

| Проверка | Что скрывает |
|---|---|
| `can('edit', 'admin', 'templates')` | карандаши в карточке и в ячейках списка, футер «Сохранить/Отменить», сам вызов `sfdSave` |
| `can('add', 'admin', 'templates')` | кнопки «Создать шаблон» и «Очистить» — вместо них текст «Нет прав на создание шаблонов» |

Право достаточно иметь в **любом** из разделов `admin` / `templates`. Право `delete` в разделе не используется — кнопки удаления шаблона в интерфейсе нет, хотя метод `CRM.deleteTemplate` существует. Видимость самих режимов управляется навигацией (`me.sections`), а не `can()`.
