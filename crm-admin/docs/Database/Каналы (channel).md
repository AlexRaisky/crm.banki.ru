# Каналы (channel)

Схема заведена миграцией `V66__channel_schema.sql` под раздел «Каналы»: во что обходится одна коммуникация и в каком состоянии канал. Подраздел на канал (`cc`, `sms`, `email`, `push`, `vk`, `fa`), экран один — тарификация у всех устроена одинаково, различается только обзор: у почты к нему добавляются данные постмастеров.

## Таблицы

| Таблица | Что хранит |
| --- | --- |
| `d_channel` | шесть каналов, подписи, порядок и флаг «бесплатный» |
| `d_cost` | статьи затрат: сумма, период суммы (в месяц / в год), период оплаты, подрядчик, комментарий |
| `d_volume` | модель тарификации: объём поштучных отправок, период, срок действия |
| `t_postmaster_daily` | метрики Google и Mail.ru Postmaster по дням + сырой ответ в `raw` |
| `app.postmaster_connection` | доступы к обоим кабинетам (строка одна, как `app.jira_connection`) |

## Почему так

**Строки с периодом, а не одно число.** Договоры и объёмы меняются. Если хранить «сколько стоит канал» одним значением, график цены назад построить нельзя, а правка объёма пересчитала бы прошлые месяцы задним числом.

**Период суммы отделён от периода оплаты.** Годовая сумма за полугодовой договор и месячная за тот же срок — разные деньги; в одном поле это не выразить.

**«Бесплатный» не стирает данные.** Флаг отключает тарификацию и обнуляет цену, но строки затрат остаются: галку снимут — всё вернётся.

**Метрики копим у себя.** Google отдаёт около 90 дней, Mail.ru ограничивает частоту (10 запросов в минуту). Без своей истории нельзя ответить, когда именно поехала репутация, — а спрашивают именно это.

## Расчёт цены

Каждая статья приводится к месячной сумме (годовая делится на 12) и раскладывается по месяцам своего периода; объём — так же. Цена месяца = затраты месяца / объём месяца. «Сейчас» — расчёт по текущему месяцу, а не последняя точка выбранного периода: иначе при просмотре прошлого года его цена выдавалась бы за актуальную. Строка без дат считается действующей всегда.

## API

`/api/channels`, права по секции `channels`: смотреть — по секции, править — по глаголу.

| Метод | Путь | Зачем |
| --- | --- | --- |
| GET | `/` | список каналов с флагом «бесплатный» |
| PUT | `/{id}/free` | переключить «бесплатный» |
| GET/POST/DELETE | `/{id}/costs`, `/{id}/costs/{rowId}` | статьи затрат |
| GET/POST/DELETE | `/{id}/volumes`, `/{id}/volumes/{rowId}` | объём |
| GET | `/{id}/pricing?from=&to=` | помесячный ряд и цена «сейчас» — для расчёта и обоих графиков |
| GET | `/email/postmaster` | сохранённые метрики и статус подключений |
| POST | `/email/postmaster/refresh` | сходить в постмастеры и обновить метрики |

Доступы правятся отдельно — `/api/admin/integrations/postmaster`, за секцией «Подключения к БД»: там лежат токены, и открывать их тому, кому выдали просмотр цен, незачем. Значения токенов наружу не отдаются — только признак «задано» и статус последней проверки.

## Постмастеры

**Google.** Версия берётся из настройки, а не подбирается по ошибке: у части кабинетов v2 недоступен, и «пробуем v2, при сбое v1» превращало бы любую сетевую неполадку в тихий откат. v1 — `domains/{домен}/trafficStats` (сутки на запись), v2 — `domainStats.query` с диапазоном дат. Скоуп `postmaster.readonly`.

**Mail.ru.** Refresh-токен меняется на часовой access в `o2.mail.ru` (client_id `postmaster_api_client`), дальше `/ext-api/stat-list-detailed/`. Заголовок нестандартный — `Bearer: <токен>`, а не `Authorization: Bearer`; с привычным написанием сервис отвечает 401 без пояснений. `spam_percent` приходит процентами и приводится к доле, иначе на одном графике оказались бы 2 и 0,02.

Домен должен быть подтверждён в обоих кабинетах, иначе API отвечает пустотой — данных не будет даже при верных токенах.
