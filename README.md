# CRM Team · Панель управления

Панель управления CRM-системы в фирменном стиле CRM Team.
Логика — как в свежих версиях Salesforce Lightning: App Launcher (вафля)
с выбором приложения, левый сайдбар разделов; у составных разделов при
наведении всплывает меню 2-го уровня, а по клику открывается обзорная
страница с блоками подразделов.

## Структура репозитория

```
crm.banki.ru/
├── crm-admin/                     ← основное приложение (Spring Boot + REST API)
│   └── src/main/resources/static/ ← ИСХОДНИК фронтенда (править здесь)
│       ├── index.html
│       ├── css/  shell.css, section-*.css
│       ├── js/   shell.js, template-list.js, template-details.js,
│       │         wizard-forms.js, dashboard.js, onelink.js,
│       │         srcbuilder.js, promo.js, entities.js, heatmap-*.js,
│       │         boot.js
│       ├── api.js, journeys.js, admin-users.js, combobox.js, wizard.js
│       ├── login.html
│       └── settings/index.html    ← настроечная админка
├── index.html, css/, js/, settings/, …  ← КОПИЯ статики в корне для GitHub Pages
└── README.md
```

**Важно про Pages.** GitHub Pages отдаёт содержимое корня репозитория
(`main` / root), поэтому статика продублирована в корень. Правки делаются
в `crm-admin/src/main/resources/static/`, после чего копия обновляется:

```bash
SRC=crm-admin/src/main/resources/static
rm -rf css js settings login.html api.js admin-users.js combobox.js journeys.js wizard.js drawflow.min.*
cp -r $SRC/css $SRC/js $SRC/settings .
cp $SRC/index.html $SRC/login.html $SRC/api.js $SRC/admin-users.js \
   $SRC/combobox.js $SRC/journeys.js $SRC/wizard.js $SRC/drawflow.min.* .
```

На Pages бэкенда нет: запросы к `/api/...` возвращают 404, интерфейс
работает в демо-режиме на резервных данных (`applyFallbackData`).

## Разделы панели

- **Главная** — настраиваемая (блоки-виджеты, drag&drop, localStorage).
- **Управление коммуникациями** — обзорная страница с блоками; подразделы:
  OneLink Builder, Мастер коммуникаций (карточка нового шаблона в том же
  оформлении, что «Просмотр настроек»: канал настроечным блоком, поля с
  подсказками «что это и какое поле в БД», предпросмотр сообщения перед
  созданием), Список шаблонов (Salesforce list view: поиск, сортировка,
  настройка отображаемых полей и фильтров через шестерёнку, правка ячеек
  по карандашу с подтверждением ✓, каналы — цветными бейджами как в
  «Планировании промо»), Просмотр настроек (канал → шаблон, поиск по
  source_type, для E-mail — по Letteros ID; карточка Salesforce Details
  с карандашами; предпросмотр — отдельным окном под карточкой, для пуша —
  проверка, помещается ли текст в карточку уведомления), Конструктор
  source, Планирование промо, Тепловая карта (только в приложении
  «Маркетинг»).

  Каналы шаблонов: SMS, Mobile-push, E-mail, КЦ, **FA** (Финансовый
  ассистент: Channel ID, Need Push, C2D-параметры, Web URL, Action
  Buttons) и **VK** (VK Template Name, TTL, AB Group, Buttons). Таблиц
  в БД для FA/VK пока нет — имена в подсказках помечены «(план)»,
  миграция появится при подключении бэкенда.

  **Цепочки** заводятся прямо в карточке мастера (секция «Цепочка»,
  каналы SMS/Push/E-mail): галочка Is chain → дни через запятую →
  «Сгенерировать строки» → таблица контента по дням; при создании на
  каждый день заводится отдельный шаблон со своим source_type. Подсказки
  полей показываются фиксированным попапом (#fieldHelpPopup) и не
  обрезаются краями карточки.

У разделов без собственного заголовка шапка описания (надзаголовок,
название, пояснение) добавляется оболочкой — `SEC_HERO` в `js/shell.js`.
- **Сущности** — данные CRM по схеме из Scheme Builder. Подразделы не
  прописаны в коде: `js/entities.js` читает ту же схему, что и Scheme
  Builder (`settings/schema/crm-schema.json` + черновик правок в
  `crmpanel:schemaDraft`), и заводит подраздел на каждую сущность —
  заведённая в Scheme Builder сущность появляется в панели сама, без
  перезагрузки (по событию `storage`).

  **Доступ.** Раздел админский: по умолчанию ни одной сущности не
  доступно никому, кроме роли ADMIN. Выдать доступ другой роли —
  реестр `crmpanel:entityAccess` = `{ <сущность>: [роли…] }`, точка
  входа `entAccessSet('client', ['MARKETER'])`. Новая сущность
  попадает в реестр с пустым списком. Раздел скрывается целиком,
  пока пользователю не доступна хотя бы одна сущность. Сущность с
  флагом **«Техническая»** (`entity.technical`) в панель не попадает
  вообще — так убран служебный справочник «Типы записей».

  **Что настраивается.** Настроечная админка → «Сущности» (Object
  Manager в духе Salesforce): список объектов, а по клику — свойства
  объекта, флаг «Техническая», порядок блоков карточки, и таблица
  полей, где для каждого поля задаются название, блок, порядок,
  показ в верхней строке карточки («В шапке») и скрытие. Настройки
  пишутся внутрь сущности (`entity.layout`) и едут вместе со схемой;
  расчёт раскладки общий для панели и админки —
  `js/entity-layout.js`.

  **Карточка записи.** Поля разложены по смысловым блокам (у клиента —
  «Персональные данные», «Документы», «Адреса», «Согласия»,
  «Стоп-листы каналов», «Доход и скоринг», «Самозапрет», «Связи»,
  «Служебные»); блоки сворачиваются. Поля, которых нет в разметке
  блоков (в том числе добавленные позже в Scheme Builder),
  раскладываются автоматически, так что сущность не теряет новые
  поля. Правка — по карандашу, подтверждается ✓ или Enter, отменяется
  ✕ или Esc, клик мимо поля сохраняет; редактор соответствует UI-типу
  поля (текст, список значений, дата, флажок, деньги, связь одним
  объектом — выпадающий список записей, связь несколькими — набор
  флажков). При сохранении обновляются `update_ts` / `user_update`.
  Есть зависимые поля: у клиента «Фактический адрес» появляется
  только после заполнения адреса регистрации, при галочке «Адреса
  совпадают» подтягивается из него и не правится вручную, без
  галочки — обычное поле для ввода.
  Связи показаны ссылками на записи других сущностей — по ним можно
  перейти; `related_list` считается по обратной ссылке из схемы.
  Записи хранятся в браузере (`crmpanel:entityData`), стартовый набор —
  по три записи на сущность с разными вариантами связок (лид с
  клиентом и без, клиент с двумя местами работы, с одним и без них,
  контакт клиента, контакт лида и контакт сразу обоих).
- **Отчёты** — обзор с карточками отчётов Tableau:
  - **Plan-Fact** — общий финансовый отчёт компании;
  - **CRM Matrix** — основной отчёт команды CRM;
  - **CRM Leadgen** — детализация: что покупают с кампании;
  - **Пример визуализации отчёта** — демо-макет окна Tableau (панель с
    книгой/листами/тулбаром, KPI и виджеты на демо-данных, полноэкранный
    режим, блок с кодом Embedding API).

  У каждого отчёта (кроме примера) — блок «Подключение к Tableau»:
  адрес Tableau Server / Cloud, опубликованная книга/лист и опциональный
  токен (JWT/PAT). «Сохранить и подключить» хранит настройки в браузере
  (`crmpanel:tableauReports`, отдельно на каждый отчёт), подгружает
  Tableau Embedding API v3 с указанного сервера и вставляет
  `<tableau-viz>`; если сервер недоступен из браузера (нет VPN) —
  показывается понятная ошибка. Сервер должен разрешать встраивание
  для домена панели.
- **Дашборд** — Общая статистика, Панель отклонений.
- **Мониторинг** — Базовая работа кампаний.
- **Загруженные инструменты** — свои HTML-страницы внутри панели
  (масштабируются под окно, оформление не меняется). Рендерятся в
  `iframe` с `sandbox="allow-scripts allow-same-origin allow-forms
  allow-modals allow-popups allow-downloads"` — то есть внутри работают
  скрипты, модалки, localStorage и скачивание файлов (экспорт из
  инструмента). Если инструмент всё же не может скачать файл, он может
  предложить фолбэк (открыть в новой вкладке / скопировать).
- **Цепочки** — только для администраторов.
- **Управление доступом** перенесено в настроечную админку (`settings/` →
  «Управление доступом»): роли и разделы пользователей, нужен запущенный
  `crm-admin` и роль ADMIN.

Очерёдность подразделов (карточки обзорной страницы и пункты меню
2-го уровня) настраивается в настроечной админке: «Приложения и
разделы» → «Очерёдность подразделов» (стрелки ↑/↓, хранится в
`crmpanel:subOrder`, открытая панель применяет изменение сразу).

## Планирование промо

Календарь промо-коммуникаций. Даты вынесены в строки-разделители на всю
ширину таблицы; «+» в конце такой строки открывает форму записи на эту дату.
Вкладки «Актуальные» / «Архивные» делят записи по дате отправки.

- **Одна запись — один канал.** «Запланировать промо-рассылку» открывает
  форму под шапкой таблицы: дата, продукт, партнёр, база, каналы, «Тотал»,
  уникальное имя, задача, ответственный, статус (по умолчанию
  «К планированию»), комментарий. Если выбрано несколько каналов —
  создаётся столько записей, сколько каналов; предпросмотр показывает,
  какие именно записи будут заведены.
- **Каналы** — множественный выбор из `callcenter, sms, e-mail, vk,
  mobile-push, fin-assistent`; выбранные всегда показываются в этом порядке.
- **Продукты** — справочник `crm_product_segment`, **партнёры** —
  `partner_name` (только латиница), **база** — многострочный текст.
- **Уникальное имя** — латиница, цифры и дефис; подставляется в название
  коммуникации.
- **Дата** — первая колонка с иконкой календаря: дату отправки можно
  переназначить, и запись сама переедет в нужный блок дат.
- **Название коммуникации** собирается автоматически по формату
  Конструктора source: `канал_promo_продукт_партнёр_уникальное-имя_ддммгг`.
- **Задача** принимает ссылку на Jira или номер (`CRM-8748`), хранит номер
  и показывает его ссылкой на `jira.banki.ru`.
- Правка ячейки подтверждается ✓, отменяется ✕ или Esc, клик мимо ячейки
  сохраняет значение.

### Правила планирования (подсветка строк)

| Правило | Отметка |
|---|---|
| 1 тотал в неделю; 2, если в уникальном имени есть `-cb` (ставка ЦБ) | жёлтый ⚠ у лишнего тотала |
| По продукту — максимум 3 промо в день, в разных каналах | красная строка |
| Не больше 4 промо в день (одна акция в разных каналах = одно промо) | красная строка |
| В день с тоталом остальные промо в том же канале | красная строка |

В архиве статус «запланировано» автоматически становится «отправлено»,
остальным показывается «Нужен статус по рассылке». Есть фильтры (месяц,
продукт, партнёр, канал, ответственный, тотал), поиск, экспорт CSV;
правки сохраняются в браузере (`crmpanel:promoPlan`, версия схемы —
`crmpanel:promoPlanVer`).

## Приложения (App Launcher)

Вафля в шапке: **Администрирование (по умолчанию) · Аналитика ·
Маркетинг · Бизнес · Контактный центр**. Набор разделов на приложение
хранится в `localStorage` → `crmpanel:appSections`, серверные права —
в `me.sections`.

## Тема и язык

Настроечная админка (`settings/`) → «Общие параметры»: тема
(светлая/тёмная/системная) и язык (русский/английский) применяются сразу
в обеих панелях, значения хранятся в `crmpanel:theme` / `crmpanel:lang`.

## Запуск

- **Фронтенд отдельно:** любой статик-сервер поверх
  `crm-admin/src/main/resources/static` (API-ошибки в консоли ожидаемы).
- **Полностью:** см. `crm-admin/README.md` и `crm-admin/DEPLOY.md`
  (Spring Boot + PostgreSQL, docker-compose).
